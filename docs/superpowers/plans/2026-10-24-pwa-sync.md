# Nihongo Quest PWA 化 + 多裝置同步 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 讓現有的單檔 HTML 學習 app 可以在 iPhone 與 Mac 上以 PWA 開啟，進度本地存 IndexedDB，並透過 Supabase 在 2～3 位登入使用者各自的裝置間同步。

**Architecture:** 原 `nihongo_quest_n4_v3.html` 改名 `index.html`，加 manifest 與 service worker 放上 GitHub Pages。`saveState/loadState` 改走 IndexedDB（localStorage 退回方案）。新增兩個檔案：`sync-core.js`（純函式，Node 可測）與 HTML 內的 `85_sync.js` 段落（Supabase 登入、debounce 推送、開啟時下拉、last-write-wins）。

**Tech Stack:** 原生 JS（無框架、無 bundler）、IndexedDB、BroadcastChannel、Service Worker、supabase-js v2 UMD（vendored）、Supabase Auth magic link + Postgres RLS、GitHub Pages、`node --test`（Node 16.20 可用）。

**Spec:** `docs/superpowers/specs/2026-10-24-pwa-sync-design.md`

## Global Constraints

- 單一 HTML 的分段慣例：新程式碼放在 `// ---- 84_store.js ----` 與 `// ---- 85_sync.js ----` 段落，位置在 `83_safety.js` 之後、`90_init.js` 之前。
- `saveState()` 維持同步簽名，48 個既有呼叫點不改。
- 所有外來 state 都經過 `normalizeState()`；套用雲端 state 時用 `keepLocalSecrets` 保留本機金鑰。
- 上傳前一律 `stripSecrets`：清空 `aiConfig.geminiKey`、`aiConfig.openaiKey`、`ttsConfig.deepgramKey`、`ttsConfig.openaiKey`。
- `SESSION` 或 `EXAM` 非 null 時不得套用雲端 state。
- SW 快取名稱 `nq-v<N>`；Supabase、Google Fonts、第三方 API 一律 network-only。
- 不 commit `Anki/`、`*.apkg`、`.DS_Store`。repo 為 public（GitHub Pages 免費方案需求），因此 `config.js` 只能放 Supabase URL 與 anon key，不能放任何 service key。
- Supabase：東京 `ap-northeast-1`、Email provider + Magic Link、密碼登入關閉。
- UI 文案一律繁體中文。
- Commit 訊息結尾加 `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`。

## Review Focus

1. 從舊備份還原的 state 沒有 `updatedAt`（或是垃圾值）→ `pickNewer` 必須把它當最舊而不是丟例外或選錯。（測試在 Task 6）
2. `aiConfig` / `ttsConfig` 為 `null` 時 `stripSecrets` 與 `keepLocalSecrets` 不能崩。（測試在 Task 6）
3. 使用者輸入 email 有前後空白或大寫 → 寄送前要正規化，否則 Supabase 會建出第二個帳號。（測試在 Task 6 的 `normalizeEmail`）
4. debounce 期間登出 → 到期時 `push()` 必須重新檢查 session，不能用舊 session 上傳。（手動驗證在 Task 8 Step 6）
5. 雲端拉下來的 state 版本 `v` 與本機不同或缺欄位 → 必須經 `normalizeState` 補齊，不能讓 `route()` 崩。（手動驗證在 Task 8 Step 6）
