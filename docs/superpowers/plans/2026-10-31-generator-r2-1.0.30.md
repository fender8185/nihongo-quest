# 產生器改成上傳到 R2（1.0.30） — 實作計畫

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 管理者的「生成雲端音檔」改成：列出 Cloudflare R2 `nihongo-audio` 已有的檔案，缺的用 Google 產生後上傳到 R2。S3 請求在瀏覽器裡簽名，不再呼叫 Supabase Storage，也不再需要 Supabase secret key。

**Architecture:** 全部改在 `index.html` 的雲端音檔區塊。
- 新的純函式 `sigV4`：AWS Signature Version 4，用 WebCrypto 計算。
- 新的 R2 用戶端：`r2ListExisting`、`r2Put`、`r2ErrorDetail`。
- `cloudGenStart(googleKey, r2)` 改用上面這些，拿掉 `cloudListExisting`。
- 管理者頁面換欄位和說明文字。
- 開始寫程式前，先在 Cloudflare 設好 CORS，再用 curl 確認 R2 的實際反應。

**Tech Stack:** 單檔 `index.html`（原生 JS，函式都是全域）；`crypto.subtle`、`DOMParser`；e2e 測試 `tests/e2e/test_fixes.py`（headless Chrome、`cdp.py`）。

**Spec:** `docs/superpowers/specs/2026-10-31-generator-r2-design.md`

**R2**

- 上傳另外帶 `Content-Type: audio/mpeg` 和 `Cache-Control: public, max-age=31536000, immutable`，跟現有的 R2 物件一樣。這兩個標頭不簽。

**文案**（spec §5、§6）
- 欄位標籤：`Google Cloud API Key`（不變）、`R2 Access Key ID`、`R2 Secret Access Key`。
- 說明文字：`把全部教材句子生成一次並上傳到 Cloudflare R2 的 nihongo-audio；日文用上面選的 Neural2 聲音，中文（單字意思、例句與文法的翻譯、漢字字義）用 Google 的台灣華語聲音，給「聽一輪」用。三把金鑰只在這一次執行中使用：不儲存、不同步、關掉頁面就消失；R2 金鑰只能讀寫這一個 bucket。已存在的檔案會略過，可以中斷再續跑。`
- 欄位沒填齊時的 toast：`三個欄位都要填。`
- 列檔名時連不上：`連不到 R2：檢查網路和 bucket 的 CORS 設定`

**不變**
- 1.0.29 的播放、離線語音、下載全部：`fetchCloudClip`、`fillAudioCache`、`sw.js`。
- Google 產生音檔的部分：`fetchEngineBlob`、`cloudAudioTexts`、`cloudAudioPath`。
- 金鑰只在執行中存在，不寫進 `state`、`localStorage`、`ttsConfig`。

## Review Focus

1. **翻頁 token 帶 `/`、`+`、`=`**：R2 的 continuation token 長得像 base64。網址和簽名要用同一種嚴格編碼，不然從第二頁起就 403。測試：Task 2 的 r2-list 範例（token `1A/b+c=`）、Task 3 的翻頁測試（token `tok/1+=`）。
2. **R2 的錯誤內容是 XML**：簽名錯、權限不夠、裝置時間差太多時，R2 回 403 加 `<Code>`（例如 `SignatureDoesNotMatch`、`AccessDenied`、`RequestTimeTooSkewed`）。錯誤訊息要顯示這個 Code，不然看不出原因。測試：Task 3 的錯誤測試。
3. **貼上的金鑰前後有空白或換行**：從密碼管理器貼上常常帶。測試：Task 4 的管理者頁面測試用帶空白的值。
4. **bucket 的 CORS 沒設好**：瀏覽器會直接擋掉列檔名的請求（TypeError）。這時要顯示「連不到 R2…」，不是英文的 Failed to fetch。測試：Task 3、Task 4 的錯誤測試。
5. **真的 R2 接不接受**：未簽的 `Content-Type`/`Cache-Control`、`UNSIGNED-PAYLOAD`、錯誤回應有沒有帶 CORS 標頭，只有真的 R2 知道。確認方式：Task 1 用 curl 檢查，Task 5 發版後使用者跑一次，Claude 抽查結果。

### Task 2：`sigV4` 簽名

**Files:**
- Modify：`index.html`，`fetchCloudClip` 後面（約 8287 行）；`APP_VERSION`（972 行）；`sw.js:2`
- Test：`tests/e2e/test_fixes.py`，加在 `test_a_clip_r2_lacks_or_cannot_serve_comes_from_supabase_and_is_no_miss` 後面，並加進 `tests` 清單

**Interfaces:**
- Produces：`async function sigV4(method, url, headers, creds, opt = {})` → `Promise<Object>`。
  - 回傳 `headers` 的副本，再加上 `x-amz-date` 和 `Authorization`；不含 `host`。
  - `creds = { keyId, secret }`；`opt = { region = 'auto', service = 's3', now = new Date() }`。
  - 簽的標頭：`host`（取自 url）、`headers` 裡的全部標頭（名稱轉小寫）、`x-amz-date`。
  - 內容雜湊：有 `headers['x-amz-content-sha256']` 就用它，沒有就用空字串的 SHA-256。
  - 查詢字串從 url 讀出來：用 `&`、`=` 切開再 `decodeURIComponent`。不要用 `URLSearchParams`，它會把字面上的 `+` 變成空白。依名稱排序後，用嚴格的 RFC 3986 編碼重新組起來（`encodeURIComponent`，再把 `!'()*` 也編碼）。
