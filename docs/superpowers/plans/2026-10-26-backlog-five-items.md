## 1. 第 0 週：給日語小白的入門講解

**現況。** 課程從 m1「格助詞」直接開始，題目標籤出現「い形容詞」「五段動詞」「て形」等名稱卻沒有任何地方解釋。講義系統已經存在：`DATA.LESSONS[uid]` 有 `formula / overview / sections[{h, rule, points, ex[{jp, zh}]}] / tip`，由 `lessonHtml()` 渲染，例句自帶播放鍵，支援 `漢字[かな]` 振假名語法。

**做法。** 新增一個不排進進度、沒有練習題的講義 `m0`，直接沿用 `lessonHtml` 的資料格式，只是章節多、內容長。建議章節：

| 章節 | 內容 |
|---|---|
| 假名與發音 | 五十音表（可點播放）、濁音半濁音、長音、促音、拗音、片假名用途、羅馬字對照 |
| 一句日文長什麼樣 | 「主題は…述語」骨架、動詞在句尾、主語常省略、句尾決定肯定否定時態 |
| 品詞：本課程用到的名稱 | 名詞、代名詞、疑問詞、副詞、接續詞；**い形容詞／な形容詞**怎麼分（看辭書形結尾、例外「きれい」「嫌い」）；**動詞三類**（五段／一段／不規則）怎麼分、常見例外（帰る、入る、知る） |
| 動詞的「形」 | 辭書形、ます形、て形、ない形、た形各是什麼、長什麼樣、後面幾週會在哪裡學到（只預告，不教變化規則） |
| 敬體與常體 | です・ます 與 だ・る，本課程題目以敬體為主 |
| 助詞是什麼 | 一句話說明は・が・を・に・で・へ・と・の 的角色，接到 m1 |
| 數字與量詞入門 | 1–10、百千萬、幾個常用量詞的音變（一つ、三本、六枚），順便說明為什麼「三」會有不同讀音 |
| 名稱對照表 | 本 app 標籤 ↔ 其他教材：い形容詞＝形容詞／イ形、な形容詞＝形容動詞／ナ形、五段＝Ⅰ類／u 動詞、一段＝Ⅱ類／ru 動詞、不規則＝Ⅲ類 |
| 這個 app 怎麼用 | 今日練習、SRS 間隔是什麼、題型、預習卡與再考、字卡與主題、設定裡該調什麼、什麼時候換單元 |

**要動的地方。**
- `DATA.LESSONS.m0` 新資料（約 2000–3000 字的 zh-Hant 內容）。
- 課程頁 `renderCourse` 最上面一張「第 0 週・開始之前」卡片（不計進度、不出題）。
- 首頁：`currentUnit === 'm1'` 且作答數少於某值時顯示一次性的橫幅「第一次用？先看第 0 週」。
- 練習中的詞性 chip（`posLabel`）與題目標籤改成可點，開一個小視窗跳到 m0 對應章節（glossary）。
- 五十音表播放鍵沿用 `speak()`。

**工作量。** 介面半天；內容是主體，需要仔細寫並由使用者過一遍是否「讀完能接上 m1」。

**要決定。** (a) 是否要五十音表（內容最長的一節，但對完全的小白最重要）。(b) 要不要也放在「更多」選單當常駐參考。

## 2. 例句常常沒有播放按鈕

**現況盤點。** 有播放鍵：講義例句、字卡背面例句、漢字詳情例字。沒有播放鍵：
- 新字**預習卡**的例句（v13 新增時漏掉）。
- 單字題**作答後的回饋**：`vocabWhy()` 把例句塞進 markdown 的 `why`，純文字；`fb-full` 整句播放只給文法題與例句填空。
- 練習頁底部的「發音」鍵只念單字，念不到例句。
- 單字表沒顯示例句（可不改）。

**做法。** 一個共用的 `exampleHtml(jp, zh, {size})` 產生「播放鍵＋振假名例句＋中文」，取代各處手寫的版本；單字題回饋把例句從 `why` 文字抽出來改用它；練習頁底部多一顆「例句」鍵（有例句才顯示）。順手把 `fb-full` 的播放鍵對所有有 `fullJp` 的單字題開放。

**工作量。** 小，半天內含測試。

## 3. 語音加入 Google Neural2，並處理「三」唸錯

**現況。** 引擎有瀏覽器內建、Deepgram Aura-2、VOICEVOX、OpenAI TTS，統一走 `engineBlob → fetchEngineBlob`，快取以文字＋聲音為 key。送出的文字由 `ttsText()` 處理（去括號、去標記），單字題的 `speakWord` 在讀音是純假名時已經用讀音而非漢字。

**做法 A：新增 Google Cloud Text-to-Speech 引擎。**
- REST：`POST https://texttospeech.googleapis.com/v1/text:synthesize?key=API_KEY`，回傳 base64 MP3；瀏覽器可直接呼叫，金鑰在 Google Cloud 限制只能用 TTS API 並綁網域。
- 聲音：`ja-JP-Neural2-B`（女）、`ja-JP-Neural2-C`（男）、`ja-JP-Neural2-D`（男），另有較新的 `ja-JP-Chirp3-HD-*` 可一起列。
- 設定頁：引擎選項「Google Cloud TTS（Neural2）」、API Key、主要聲音、對話男聲，照 OpenAI 那組的樣子。
- 價格：Neural2 每百萬字元 16 美元，每月前 100 萬字元免費；本 app 一天用量約數千字元。

**做法 B：讀音修正（對 Deepgram 也有用）。**
- Google TTS 支援 SSML：對已知讀音的字用 `<sub alias="さん">三</sub>`，漢字保留給模型判斷語調，讀音由我們指定。資料來源：單字的 `r`、例句的 `{}` 標記字、`FURI` 字典（`furi()` 已能產生 ruby，可反推出 kanji→reading 對照）。
- Deepgram 不支援 SSML，只能把整句或部分字轉成假名再送。全部轉假名會傷語調（Neural 模型靠漢字斷詞），所以做成**只替換「我們確定讀音」的字**，其餘保留；並加一個設定「朗讀前把已知讀音的字轉成假名」預設開啟。
- 數字量詞（三本＝さんぼん、三つ＝みっつ）：單字資料有讀音就用讀音；句子中的數字＋量詞用一張小表處理最常見的 1–10 × 常用量詞，查不到就保留原文。

**工作量。** A 半天；B 一天（含測試：含數字的例句送到引擎的字串正確）。

**要決定。** 是否申請 Google Cloud 專案與金鑰（需要信用卡綁定，免費額度內不扣款）。沒有金鑰也可以先做 B。

## 4. 手機 Brave：設定視窗頂端被卡住，關不掉也切不了分頁

**現況。** ≤600px 時 `.modal-back { place-items: end stretch }`、`.modal { max-height: 92vh }`，視窗貼底、往上長。標題列是 `position: sticky; top: 0`，在 `.modal` 內捲動。手機瀏覽器的 `vh` 以「工具列收起」的最大高度計算，Brave 的網址列在上方且會隨捲動收合：工具列展開時，92vh 的面板頂端被網址列蓋住，sticky 標題（關閉鍵、分頁按鈕）就在看不到也點不到的地方。背景的 `backdrop-filter` 在 Brave 也有已知的重繪問題。

**做法。**
- 高度改用小視口單位：`max-height: calc(100svh - 12px)`（`dvh` 作為支援時的進階），並加 `padding-top: env(safe-area-inset-top)`。
- 標題列改成不在捲動區內：`.modal` 改為 `display:flex; flex-direction:column`，`.modal-head` 固定、`.modal-body` 才 `overflow:auto`。這樣不論視口怎麼變，關閉鍵永遠在面板第一行。
- 面板底部加一顆「關閉」按鈕作保險，並允許點背景關閉（目前是否支援要確認）。
- 移除或改弱 `backdrop-filter`（改純半透明底色）。
- 驗證：Chrome headless 模擬 390×700 視口並改變 viewport 高度，確認關閉鍵的 `getBoundingClientRect().top ≥ 0`；真機由使用者在 Brave 上確認。

**工作量。** 小，半天。

## 5. 文法課程進度條多一兩種顏色

**現況。** `unitStats()` 以每題等級（上限 3）加總算出 `pct`，課程頁卡片、單元頁、首頁「目前單元」各畫一條單色進度條。

**做法。** 把主題卡的 `stackBarHtml` 一般化為「總數＋若干段」，文法用三段（不超過三色）：
- **答對 3 次以上**（`r.ok ≥ 3`）
- **答對過**（`r.ok` 1–2）
- **出現過但還沒答對**（有紀錄但 `ok = 0`）

未出現過的留白。`unitStats` 多回傳 `ok3 / ok1 / seen0` 三個數；三個地方換成三段條，百分比文字改成「答對過 x／熟練 y／共 n」。圖例沿用主題卡的小方塊。

**工作量。** 小，半天含測試（和主題卡的測試同一套寫法）。

**要決定。** 三段的門檻用答對次數（使用者的描述）還是沿用等級（b）？建議用答對次數，和使用者的直覺一致，也和 v19 的「答對次數最少優先」出題邏輯對得上。
