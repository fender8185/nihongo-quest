## 1. 目標

使用者（2026-11-12）：「npc 還是太死氣沉沉，也許要讓他們會移動？大部分的居民好像很愛說…，好像需要讓他們多一些變數？」

現況（1.13.0）：
- 居民站在 `events.js` 的 `TOWN.SPOTS` 固定點上（`TOWNEV.castHtml`），只有食堂、居酒屋裡剛和鉄平的手、坐著的人點頭、ムギ搖尾巴會動。
- 事件裡居民說的 739 句有 413 句帶「……」，215 句一開頭就是「……」（陽菜 55/73、小春 41/60、ゴウ 29/30、佐野 24/33）；主角 23 句裡 14 句。
- 沒事件時點居民（`TOWNEV.chatLine`）：每人 3–5 句隨機抽，不看時間、地點、劇情、主角的樣子；和子沒有閒聊，永遠是「……」。

使用者選的（2026-11-12）：
- 會動：在自己的點附近走走停停；頭上冒泡泡（自言自語、兩個居民互相聊）；換時段時看得到他們走出去、走進來。不要無名路人。
- 閒聊跟著變：時間和地點、劇情進度、主角的樣子、越聊越熟＋聊別人＋節日。
- 「……」：大幅減少（約一成）。

不變的事：事件的觸發、內容的意思、選回答的題目和選項、言靈、學習排程、小春和ムギ的來訪。

## 2. 居民會動（TOWNLIFE）

新的一段程式 `TOWNLIFE`，放在 `js/71c_town.js` 的 `TOWNEV` 之後（檔案已經 2155 行；若加完超過約 2500 行，拆成 `js/71i_life.js`，照 index.html 的 `<script>` 順序和 sw.js PRECACHE 加上）。它管一個畫好的場景（`.yard`）裡居民的位置和動作；場景被移掉（`yard.isConnected` 為假）就停。

### 2.1 誰會走

- 室外地點（`town`、`beach`、`street`、`harbor`、`park`、`station`、`sento`、`shrine`、`castle`）站著的人。
- 不走：`sit`、`kneel` 的點；食堂、居酒屋（45° 的室內）裡的人；頭上有「！」（`host`）的人。不走的人照樣做 §2.3 的小動作。
- 每個點可以在 `TOWN.SPOTS` 裡加 `roam`：
  - `roam: [dx, dy]`：可以走的範圍（預設 `[70, 18]`，以點為中心左右 dx、前後 dy）
  - `roam: 0`：不走
  - `run: 1`：用跑的（美玖在公園）
- ムギ（`NPC.art`，沒有腿）走的時候整個身體上下跳（新的 CSS 動作），不是邁腿。

### 2.2 怎麼走

- 每個人自己一個計時器：停 4–10 秒（亂數），再往範圍內隨機一點走 1–3 秒。
- 路線用 `yRoute(place, from, to)`（繞開 `WALK_BLOCK`），範圍外的點、`walkTop` 以上的點夾回來。
- 走的時候加 `.walk`（`run` 為 1 時 `.run`），方向用和 `yHeroWalk` 一樣的 `back / turn / flip`；位置寫進元素的 `transform`，同 `castHtml` 的算法（`yScale`、`z-index: 300 - Y`）。
- 只有有人在走時才跑一個 `requestAnimationFrame` 迴圈（整個場景共用一個）；沒人在走就只剩計時器。
- 每個人目前的位置記在 `TOWNLIFE` 裡（不存檔）；重畫場景時回到自己的點。

### 2.3 小動作

停下來時，有一半的機會做一個小動作，用主角已有的動畫：東張西望（`heroLookRound`）、伸懶腰（`heroUpL`/`heroUpR`）、點頭（`heroNod`）、晃一晃（`heroSway`）、跳一下（`heroBounce`）。用一個 class 加上去、1.5 秒後拿掉，和 `yUse` 的 `t.pose` 同一種寫法。

### 2.4 和主角的互動

- 主角走到 120px 內（`yHeroPlace` 時檢查）：這個人停下、轉向主角；同一次進這個地方，每個人最多揮手（`heroWave`）一次。
- 點一個人（`TOWNEV.talk`）：他當場停住；主角走到他**當下**的位置旁邊（`talk()` 改用 `TOWNLIFE.at(id)`，沒有就用點的位置）；`TALK` 關掉後再繼續。
- `TALK.on()` 時所有人停住、不冒泡泡。

### 2.5 頭上泡泡

- 每 8–15 秒，從畫面上的人裡挑一個（不在走、不是正在對話的），在他頭上冒一句短日文，2.5 秒後淡出。泡泡跟著他的位置，有振假名（`TALK` 的 ruby 寫法），不唸、不顯示中文、點不到（`pointer-events: none`）。
- 句子：`TOWN.MUTTER[id]`，每人 4 句左右，格式同 CHAT（§3.1，可以帶條件），一樣照單元擋。
- 兩人對話：同一個地方兩個人都在、都認識時，有三分之一的機會改成 `TOWN.PAIRS` 裡他們的一組：
  - 兩人相距超過 160px 時，會走的那一個先走到另一個人旁邊（小鎮的店前後相隔很遠）；兩個都不能走（室內、坐著）就留在原地。
  - 站著的兩人轉向對方（坐著的不轉身），輪流冒 2–3 個泡泡，每個間隔 2 秒，期間都不走；說完走過去的那個人走回自己的範圍。
- `TOWN.PAIRS`：`[[a, b], unit, [[who, ja], [who, ja], …], when?]`。19 組，只給真的會同時在同一個地方的人（2026-11-12 照 `CAST.hours` 算過）：
  - 小鎮：健太／美玖、陽菜／和子、美玖／陽菜、小春／林、健太／渚、小春／佐野
  - 食堂：トメ／ゴウ、トメ／鈴木
  - 居酒屋：鉄平／健二、中村／西村、鉄平／中村
  - 站前：原田／小林、鈴木／原田、タロウ／小林
  - 澡堂：松／源三
  - 神社：千早／タツ
  - 城：高橋／ソフィア
  - 海邊：健二／ムギ、アレックス／ムギ
- 系統設定「減少動態」時照樣有泡泡（只有淡入淡出）。

### 2.6 換時段：走出去、走進來

- `sceneMinute` 看到 `sig` 變了、而且這次只差在人（不是店門、緣日）：先叫 `TOWNLIFE.leave(place, ids, done)`。
  - 要走的人：朝 `hop(place, 他下一個地方)` 的出口走（`WAYS[place>next].out()`；沒有這條路的地點、或他今天不再出現，就走向比較近的畫面邊緣），到邊緣淡出（`.out`）。
  - 全部走完（最多 4 秒）再 `route()` 重畫。
- 重畫後，剛到的人（上一次 `sig` 沒有、這次有的）從來的方向那一邊的入口（`WAYS[from>place].in()[0]`；沒有就畫面邊緣）走到自己的點。
- 主角剛進這個地方（`yh.arrive` 有值、或場景是新開的）時，原本就在的人直接站著，不走進來。
- 睡覺跳時間（`NAP.to`）、`町の手帳` 改時間：照舊整個重畫，不做動畫。
- 店門開關、緣日開始時也照樣做走出走進（實作時改的：人換班常常就在店打烊那一刻，例如渚 18 點關喫茶店），走完再重畫，店門跟著換。
- 同一個地方換點的人（千早 18 點從拜殿到緣日的籤攤）從原本的位置走過去。

### 2.7 減少動態、效能、測試開關

- `prefers-reduced-motion: reduce`：不走、不做小動作、不走出走進；泡泡照舊。
- 頁面切到背景（`visibilitychange`）：計時器和迴圈停下；回來再開始。
- `TOWNLIFE.still = true`：所有人站在自己的點上不動、不冒泡泡。e2e 的共用前置（`FRESH`、`test_town_events.py` 的 `go`）設成 true，原有點居民、量位置的測試不受影響；新的測試自己把它關掉。

## 3. 閒聊有變化

### 3.1 台詞格式

`TOWN.CHAT[id]` 一句仍是 `[unit, ja, zh]`，可以多一個第四格 `when`（物件，各欄都可以不寫）：

| 欄 | 意思 |
|---|---|
| `at` | 地點（`'beach'`、`'izakaya'`…），或陣列 |
| `h` | 時段：`'am'`（5–11 點）、`'noon'`（11–15）、`'pm'`（15–19）、`'night'`（19–5），或陣列 |
| `days` | `'wd'` 平日、`'we'` 週末 |
| `after` | 這個事件完成之後才說 |
| `before` | 這個事件完成之前才說 |
| `fresh` | 這個事件完成後三天內，**新消息**（§3.2） |
| `talks` | 和這個人閒聊過至少幾次（3、8、15） |
| `look` | **新消息**：`'any'` 主角的樣子（look 或 wear）和這個人上次看到的不一樣；`'hair'` 頭髮那幾欄變了；或一件古道具屋東西的 id（正穿著、而且這個人沒看過） |
| `fest` | 節日，**新消息**：`'halloween'`（古道具屋 `SALES.halloween` 的日期，伺服器的日子） |
| `about` | 聊到的另一個居民；主角認識那個人（`TOWNEV.seen`）才說 |

時間、日子用 `TOWNEV.now()`／`TOWNEV.today()`（睡覺、`町の手帳` 的時間也算）。小春、ムギ在 `NPCS[id].chat` 的閒聊搬進 `TOWN.CHAT.koharu`／`TOWN.CHAT.mugi`（標 `m0`），`NPCS[id].chat` 拿掉。`TOWN.MUTTER` 用同一個格式。

### 3.2 怎麼挑（`TOWNEV.chatLine(id)`）

1. 可以說的：單元已到（`unitIdx(u) <= reachedIdx()`）、`when` 的條件都成立。
2. 新消息優先：帶 `fresh`、`look`、`fest` 的句子，可以說、而且這台裝置還沒說過的，挑第一句說，記成說過（`fresh` 每個事件一次、`fest` 每年一次、`look` 每次換樣子一次）。
3. 不然從其他可以說的句子裡抽：帶 `at` 或 `h` 的權重 2，其他 1；這個人最近說過的 5 句不抽（全都說過就忽略這條）。
4. 一句都沒有：回到 `['……', '……']`（只有程式出錯時才會看到；§5 的檢查擋掉沒閒聊的人）。
5. 每次閒聊（不是事件）這個人的次數 +1，並記下他這次看到主角的樣子。

### 3.3 記在哪裡

- `state.town.talks`：`{ id: 次數 }`，跟著存檔同步。`js/40_core.js` 的正規化（`out.town = { … }`）加 `talks: obj(tw.talks)`；`sync-core.js` 的 town 合併加 `talks`，每個 id 取兩邊比較大的數字；`sync-core.js` 開頭的說明一起改。
- `localStorage.nq_chat`（只在這台裝置）：`{ said: { id: [最近 5 句的 key] }, news: { key: 1 }, saw: { id: 樣子的簽名 } }`。句子的 key = 人 + 日文原文。讀寫都包 try/catch；沒有 storage 時照樣能聊，只是會重複。

### 3.4 台詞份量

每人大約 18 句（和子、全部人都有；外婆只出現在信裡，不加）：

| 類型 | 每人 | 寫法 |
|---|---|---|
| 日常 | 約 6 | 隨 `at`、`h`、`days` 變：早上的招呼、晚上的招呼、在不同地點說不同的事（健二在海邊、漁港、居酒屋各有話） |
| 劇情 | 4–6 | 跟著他自己的事件線：`after`／`before` 讓話題隨故事換，`fresh` 是剛發生的事 |
| 你的樣子 | 2–3 | `look: 'any'` 一句；小春另有 `look: 'hair'`；特別的穿搭（貓裝、翅膀、狐狸面具、太陽眼鏡、ランドセル…）分給適合的人 |
| 越聊越熟 | 3 | `talks: 3 / 8 / 15`，越後面越像朋友、說心裡話 |
| 聊別人 | 1–2 | `about`，像松阿嬤什麼都知道、西村愛傳消息 |
| 萬聖節 | 1 | `fest: 'halloween'` |

另外 `MUTTER` 每人約 4 句（短，最多約 12 個字），`PAIRS` 19 組。新台詞合計約 500 句閒聊＋110 句泡泡＋50 句兩人對話。

口氣照 `CAST[id].bio`（敬體／常體、口頭禪、ムギ的「ワン」、林偶爾一句中文的寫法 `['m0', '', '（用中文）…']`）。每句照樣：漢字一律 `{漢字|かな}`，超出那個單元程度、或課程沒有的字加中文 `{漢字|かな|中文}`。

### 3.5 口吻表（寫台詞之前先做）

使用者問「他們都有從這些少少的台詞中展現出個性嗎」（2026-11-12）。看下來：敬體／常體大致分得開，可是
- 9 個人的閒聊一開口都是「いらっしゃい（ませ）」（健太、陽菜、林、渚、ゴウ、トメ、鉄平、タツ、松）；
- 話少的ゴウ、健二被大家都在說的「……」淹沒；
- 設定好的特點沒出現：健太什麼都要數、タロウ想當音樂人、タツ偷偷多送一隻金魚、剛想改菜單、美咲熟了改用常體唸你；
- 小春的舊閒聊（「波の音を聞くと、落ち着く」）是她還在海邊時寫的；
- 入門就認識的人能用的字很少，個性只能靠自稱、句尾、口頭禪、節奏。

所以先寫 `docs/town-voices.md`：每人一段，

使用者交給我照建議做（「全照你的建議來，一直到推上 test 版本」），口吻表不另外等使用者看；寫台詞的助手、事件「……」的改寫都照它。之後使用者覺得誰的個性不對，改這份表再照表重寫那個人。

## 4. 事件裡的「……」

- 目標：居民事件台詞帶「……」的從 413/739 句降到 70 句左右（約一成）；開頭就是「……」的只留少數。主角的 14 句照同樣原則看。
- 留下：真的沉默、猶豫、說不出口的時刻（例如陽菜說要去東京之前、佐野被問到海的那一下、外婆的信）。
- 話少的人（ゴウ、健二、佐野）改用短句、「ん」「ああ」「おう」來表現，不靠「……」。
- 其他人換成各自的口頭禪或直接拿掉：陽菜「は？」「べつに」、小春「ねえ」「えっと」、アレックス「ええと」、高橋「さて」、健太「おっ」、トメ「ほら」等。
- 中文跟著改，不再每句跟著「……」。
- 不動：事件的意思、`ask` 的題目、`opts` 的選項和解說、句子的單元程度、`EVENTS_VERSION` 以外的結構。
- 改過的句子語音要重做（§7）。

## 5. 檢查（`scripts/check-events.js`）

新增：
- 「……」比例：居民事件台詞帶「……」超過 12%、或 CHAT 超過 10%，報錯（`ellipsis`）。
- `when` 的每一欄：地點在 `TOWN.PLACES`、時段和日子是上面的值、事件 id 存在、`about` 是 `CAST` 的人、`look` 是 `'any'`／`'hair'` 或古道具屋有的東西 id（從 `js/71d_wares.js` 讀 id 清單）、`fest` 是已知的節日。

- 每個 `CAST` 的人（外婆除外）至少有 10 句 CHAT，其中至少兩句沒有 `when`、單元不晚於他第一個事件（認識他時一定有話說，不會只回「……」）。
- `TOWN.SPOTS` 的 `roam` 是 0 或兩個數字。

3. 閒聊新規則＋新台詞＋事件「……」改寫＋檢查（§3–5）；`EVENTS_VERSION` 加一，index.html 的 `<script src>` 和 sw.js PRECACHE 一起改

第 3 步先寫口吻表（§3.5），再把台詞按地點分四組，交給助手同時寫：小鎮店家（健太、美玖、陽菜、和子、林、渚、小春、佐野）、食堂居酒屋（トメ、ゴウ、鉄平、美咲、中村、健二、鈴木、西村）、站前公車澡堂（タロウ、原田、小林、松、源三）、神社城堡海邊（千早、タツ、高橋、ソフィア、アレックス、ムギ）。事件「……」的改寫也照這四組，各組改自己人的台詞。寫完我逐組看口氣和程度，再跑 `check-events.js`。

正式版之後使用者要做的：重新整理後按「雲端音檔 › 生成」，改過的事件台詞＋新閒聊大約 850 個語音（泡泡不唸，不用生成）。

## 8. 不做的事

- 無名路人（使用者沒選）。
- 居民在地點之間真的走一整段路（只走到出口淡出、從入口走進來）。
- 泡泡唸出聲、泡泡顯示中文。
- 好感度數值、送禮給居民等系統（「聊過幾次」只用來選台詞）。
