# 分層 queue 出題規則 — 設計

日期：2026-10-30　狀態：使用者已逐段確認（2026-10-30），授權直接實作　版本：1.0.20（接在 1.0.19「今天的清單」之後）

## 1. 問題

1. 階段測驗通過後批次標記兩千多題，第一次複習雖然分散了（每天最多約半個負荷上限），但答完第一次後還會再回來，跟陸續到期的第一次複習疊在一起。模擬：負荷上限 100，標記後第 8 到 39 天每天都超過上限，最高 173 題；新題從每天約 21 題被壓到 10 題，維持一個月。
2. 新題數由「每天負荷上限」推算，跟使用者實際消化得了多少無關。記性差的人固定每天 15 個新題時，每天要做 133 題，錯題本超過 100 條。

## 2. 使用者的決定

- 三顆以下照傳統的間隔複習（FSRS），星星依記憶強度計算。四顆、五顆、錯題本各自是一個 queue，每天出固定比例，等最久的先出。
- 四顆答對升一級變五顆。五顆答對排回隊伍最後。入門的題目在五顆答對就移出，之後不再出現。不管在哪一層，答錯都照一般流程重練並進錯題本。
- 三顆以下的到期複習每天最多 50 題。
- 拿掉每天負荷上限。新題數看最近 100 題的正確率和錯題本大小，原則是消化得掉比趕考試重要。
- 新題總數照各題庫還沒學的比例分給單字、文法、漢字。
- 加練只給新題，一輪的量等於今天的新題數。
- 通過階段測驗時自動把範圍內的題目設成四顆，不再讓使用者選等級。入門測驗一律改成回答四題，選三到五顆。
- 聽力、閱讀維持自己的規則，不進 queue。

模擬依據：`scripts/sim-schedule.js`（§10）。用 app 自己的 FSRS 模型、每天把排程做完、學 9 個月、一個月後考試時，考試當天平均記得 93–97%。每天的量會自己穩在 80–90 題，記性差的人會自動放慢。

## 3. 分層

只套用在單字（`v:`）、文法（`g:`）、漢字（`k:`）、假名（`a:`）、變化練習（`c:`）。聽力（`l:`）、閱讀（`r:`）不分層。

```
tierOf(key):
  沒有紀錄                                → 'new'
  r.out                                   → 'out'   入門題目已移出
  r.rl 是數字（重練中）或 r.b ≤ 3          → 'srs'   三顆以下
  r.b === 4                               → 'q4'
  r.b ≥ 5                                 → 'q5'
```

- 星星是 `srsDots(r.b)`：b 為 3、4 時顯示三、四顆，b ≥ 5 時顯示五顆。所以 queue 直接看 `r.b`，不另外存「在哪一層」。
- `isDueToday(x)` 只對 `'srs'` 層成立：`tierOf === 'srs' && r.due <= 今天 && r.last !== 今天`。聽力、閱讀照舊看日期。單元／單字／漢字練習（`scopeQueue`）因此只把三顆以下的到期題當「到期」；四顆、五顆的題目會在「不到五題時補最不穩的題」那一段出現。

## 4. 作答後的升降（`srsAnswer`）

在原本的 FSRS 計算之後：

- 答對而且答之前 `before === 4`：`r.s = max(r.s, LEVEL_FROM_S[4])`（21 天），重算 `r.b`，所以至少五顆。
- 答對、答之前 `before ≥ 5`，而且是入門題目：`r.out = 1`。入門題目指假名、PRE_N5 的內建單字、`m0` 的文法，用 `isPreItem(key)` 判斷。
- 答錯：`delete r.out`，其餘照原本：`b` 降到 1 以下、進重練、進錯題本。

這些規則在哪裡作答都一樣，包括字卡、錯題循環、單元練習，因為升降看的是星星，不是從哪一層抽出來的。

## 5. 每天的清單（`computeDailyPlan`）

1.0.19 的「今天的清單」機制不變：當天第一次需要時算好、存起來。這一版改的是怎麼算：

| 部分 | 規則 |
|---|---|
| 三顆以下的到期複習 | 範圍照現在（單字看 `vocabEligibleForDaily`／入門的規則，文法看 `grammarInReach`，N4 漢字等 N5 學完，假名照 `kanaPlan`，變化練習看已到的單元），`isDueToday` 為真的題，照到期日排，最多 50 題（`SRS_DAILY_CAP`）。 |
| 四顆 queue | 同樣範圍內 `tierOf === 'q4'`、今天沒答過的題，照 `r.last` 由舊到新，取 `clamp(round(0.05 × 數量), 1, 30)` 題；queue 是空的就是 0。 |
| 五顆 queue | 同上，`'q5'`，比例 3%。 |
| 錯題本 queue | `activeMistakes()` 裡今天沒答過、也不在上面幾項的錯題，照 `mistakeLast(m)` 由舊到新，取 `clamp(round(0.10 × 還沒清掉的錯題數), 1, 30)` 條。對到課程的錯題當成那一題出；手動錯題當成錯題卡出，key 記成 `m:<id>`。 |
| 聽力 | 每天最多 3 題（`LISTEN_PER_DAY`），先到期再新題，其餘照現在。 |
| 閱讀 | 每天 1 篇，照現在。 |
| 新題 | §6。 |
| 變化練習 | 已到的單元裡、還沒開始的變化練習，每天最多加 1 種，不佔新題名額。 |

`plan.lists` 多三個清單：`q4`、`q5`、`mk`。`buildDailyQueue` 把它們跟到期複習放在同一邊（「複習」那一側），再跟新題交錯；手動錯題卡用現有的 `{ mistake }` 項目格式。離線語音的 `audioPrefetchItems` 改成取今天清單裡的全部項目。今日頁範圍分頁的「待複習」把四顆、五顆、錯題本也算進去，並分開列出各幾題。

## 6. 新題

### 6.1 今天幾題（`newCountToday`）

```
acc = 最近 100 題的正確率（state.recent 從最多 60 筆改成最多 100 筆；作答不到 30 題時視為沒有資料）
base = acc ≥ 0.9 ? 20 : acc ≥ 0.8 ? 15 : acc ≥ 0.7 ? 10 : 5      // 沒有資料時 15
n = clamp(base − floor(還沒清掉的錯題數 / 10), 3, 20)
```

算一次，存成 `plan.n`，當天不變。`state.recent` 只收練習的作答；模擬考在 1.0.19 已經不算。`adaptiveFactor()` 刪除，它在今日頁的提示改成：n 比 base 少、或 base 小於 15 時，在說明裡寫「最近 100 題正確率 X%、錯題本 Y 條，今天新內容 n 題」。

### 6.2 怎麼分（`splitNew`）

- 題庫：正課是單字（內建單字）、文法（`REG.grammar`）、漢字（`REG.kanji`）；入門期間是假名、PRE_N5 單字、`m0` 文法。
- 每個題庫還沒學的題數，就是它的權重。名額用最大餘數法分配，總數剛好等於 n。
- 依序取各題庫現有的候選：`newVocabCandidates`、`newGrammarCandidates`（入門用 `unitNewOrder('m0')`）、`newKanjiCandidates`、入門的新假名。某個題庫的候選比分到的名額少（例如 N4 漢字要等 N5 學完、入門的假名門檻還沒開），多出來的名額按權重依序讓給其他題庫。
- 入門期間原本的規則照舊：假名門檻開之前只出假名。

`plan.split = { v, g, k, a }` 記下各題庫分到幾題。字卡的新卡名額、單元練習和單字練習的新題名額、漢字頁原本都用 `newQuota(kind) − state.today.newX`，改成 `plan.split[kind] − state.today.newX`。

### 6.3 拿掉負荷上限

- 刪除 `newQuota()`、`NEW_SHARE`，以及 `computeDailyPlan` 裡超過上限就減新題的那一段和它的提示文字。
- 設定頁拿掉「每天負荷上限」那一列。`EXPERIENCED_SETTINGS` 拿掉 `loadCap`。舊資料裡的 `settings.loadCap` 留著不管。
- 主題線長度 `laneCap()` 改成固定 `THEME_LANE_DAYS × 8`。
- 批次標記分散到期日用的 `bulkDailyBudget()` 改成固定 50，跟三顆以下的上限一致。

## 7. 加練

- 出現時機不變：今天的清單全部做完（`remaining === 0`）。
- `extraQueue()` 改成只給新題：數量 = `plan.n`，用 §6.2 的分法，但排除今天的清單和今天答過的題目；拿掉「明後天到期的提前複習」。
- 一輪就是一組練習；做完回到今日頁，只要還有新內容，就再出現「加練・N 題」。
- 說明文字改成「今天的進度已完成，這組是 N 題額外的新內容」。

## 8. 測驗與標記

### 8.1 通過階段測驗（p1–p3）

- `finishStageTest()` 在通過時直接標記：範圍是 `stagesUpTo(stage)` 的題目，排除聽力、閱讀，只處理還不到四顆的（沒有紀錄或 `b < 4`）。排除這次測驗答錯的題目，也排除還在錯題本裡的題目。
- 被標記的題目：`s = LEVEL_FROM_S[3]`（10 天），`b = 4`，其他照現在 `bulkApply` 的寫法（新紀錄記 `intro`、沒有 `lrn` 就補、`last` = 今天、到期日照「熟悉」的分散規則，這個日期只在退回舊版時才有用）。
- 聽力、閱讀照現在「熟悉」等級的規則標記（`spreadDueLR`）。
- 其他副作用照現在的 `bulkMark()`：單元完成、講義看過、`stage = 'main'`、`currentUnit` 往前。
- 跟現在一樣留一份快照，可以按「復原」。結果頁寫「已把第 X 階段以前、還不到四顆的 N 題設成四顆」，旁邊放「復原」。
- 刪除「標記到這裡為止」按鈕和它的等級對話框（`bulkMarkDialog`、課程頁 stage-foot 的那顆按鈕）。這個版本以前就通過、但沒標記的階段，重考一次就會標記。

### 8.2 入門測驗

- 通過後一律進入四題（平假名、片假名、入門單字、第 0 週句型），包括 1.0.17 舊帳號自動標記的那一份（`T.auto` 不再自動套用）。
- 選項改成三個：三顆、四顆、五顆。
- 每一類先預選：該類答對率 ≥ 90% 選五顆，≥ 80% 選四顆，其他選三顆。預選的選項標「建議」，按 Enter 或直接點都可以。
- 套用（`preMarkApply`）：三顆 = 現在的「熟悉」（`s = 5`，`b = 3`），四顆 = §8.1 的四顆，五顆 = 現在的「熟練」（`markKnown`）。
- 不再有「不記得」，所以入門四題不再設 `introPending`；1.0.17 已經設過的照舊。

### 8.3 我會了

`markKnown()` 的寫法不變（`b` 變成 6，就是五顆），所以這一題直接進五顆 queue。提示文字從「約六週後再確認一次」改成「之後會排進五顆的複習」。單字表整批我會了也一樣。

## 9. 考試倒數

- `planAdvice()`、`planAdviceHtml()` 不再推薦負荷上限，也拿掉「套用」按鈕。
- 改成：最近 14 天平均每天新學幾題，照這個速度，單字、文法、漢字還沒學的題目預計哪天學完；跟「考前三週」比，早或晚幾天。
- 「每天新學幾題」用新欄位 `dailyLogs[日期].fresh`：`srsAnswer()` 遇到第一次作答（`isNew`）時加 1，標記不經過 `srsAnswer`，所以不會灌大速度（`r.intro` 會被批次標記寫成標記那天，不能用）。還不到 14 天資料時，用有資料的天數平均；完全沒有時用今天的 `plan.n`。
- 會晚的話，寫出每天需要幾題新的、比現在多幾題，建議做加練。
- 模擬考頁上方那一行建議也改用同一段文字。

## 10. 模擬程式

`scripts/sim-schedule.js`：用 Node 從 `index.html` 抓出 FSRS 的常數和函式，模擬三種學習者照 §3–§7 的規則學 300 天，印出每天的題數、錯題本大小、多久學完、考試當天平均記得多少。以後調整 5%、3%、10%、50、新題規則這些數字時可以重跑。不在 `scripts/test.sh` 裡跑。

## 12. 測試

新增 `tests/e2e/test_queues.py`，先寫、先看它失敗，再改程式：

1. `tierOf`：各種星星、重練中、`out` 的分類。
2. 四顆答對變五顆；五顆答對 `last` 更新，排到隊伍最後；入門題目五顆答對設 `out`，之後不進清單；答錯時清掉 `out`，題目回到三顆以下。
3. 清單：四顆 queue 40 題時抽 2 題、700 題時抽 30 題（上限）、1 題時抽 1 題；五顆 100 題時抽 3 題；錯題 25 條時抽 3 條；都照 `last`／`mistakeLast` 由舊到新。
4. 三顆以下到期 80 題時，清單只放最舊的 50 題，其他明天。
5. 新題數：正確率 95%、錯題 0 → 20；85%、錯題 34 → 12；60%、錯題 200 → 3；作答不到 30 題 → 15。
6. 分配：照還沒學的比例，總數等於 n；漢字被擋住時名額讓給其他題庫。
7. 變化練習一天最多新加 1 種。
8. 加練：只有新題、題數等於 n、不含今天清單裡的題目；做完一輪後還能再加。
9. 通過 p1：範圍內不到四顆的變四顆，答錯的題目和錯題本的題目不動，聽力、閱讀照舊；復原能還原。
10. 入門測驗：四題的預選照答對率；選三、四、五顆分別寫成 b = 3、4、6；1.0.17 舊帳號也進四題。
11. 設定頁沒有「每天負荷上限」；考試倒數顯示預計學完的日期。

另外跑一次全部既有 e2e。用到負荷上限或舊等級對話框的既有測試，照新規則改寫。
