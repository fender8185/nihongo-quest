# 今天的清單、今日數字與模擬考獨立 — 設計

日期：2026-10-30　狀態：使用者已逐段確認（2026-10-30），授權直接實作　版本：1.0.19（接在 1.0.18 離線語音之後）

## 1. 問題

使用者回報（2026-10-29）：做測驗後，今日頁的圓圈數字亂跳；練習框框的數字和「今日練習」的題數對不起來。用 headless Chrome 在 1.0.15 和 1.0.17 上重現，原因有四個：

1. 圓圈的「已做」是「`srs.last` 等於今天」的題數。「標記到這裡為止」、入門三題、1.0.17 的入門自動標記和「我會了」都會把 `last` 設成今天，所以標完一個階段，圓圈從 12／21 跳到 2040／2045（1.0.17 入門自動標記：12／104 → 233／325）。同一個判斷也讓當天的聽力、閱讀、變化練習上限被吃光。
2. 正確率係數 `adaptiveFactor()` 每答一題重算一次，所以一天的總數會在答錯幾題後變動，例如 102 → 99。
3. 「題」有三種意思：圓圈算題目，開始按鈕算一組（上限 `sessionSize`，會剩下只有 1 題的第二組），「今天做了」和側欄「今日」算按鍵次數，包含再練一次、換個方式再考和模擬考的每一題。
4. 模擬考會改熟練度（`srsAnswer`）、進錯題本、算進正確率和題數。模擬考的題庫不夠時，會從整個級別的單字、文法補題，所以會把還沒學到的內容帶進排程和錯題本。

## 2. 使用者的決定

- 模擬考是另外一回事：不改熟練度、不算答題數、不算正確率，答錯也不進錯題本。只留模擬考自己的紀錄：考試紀錄、回顧、每題考過幾次（`questionHistory`）。
- 舊資料不處理：以前模擬考留下的錯題、熟練度、作答次數都不轉換。
- 今天的題目在當天第一次需要時排好、記下來，當天不重算。代價是：當天中途才解鎖的新內容，例如標記後單元往前推進，要明天才排進來。
- 圓圈只畫百分比，不顯示題數。
- 「今天做了」和側欄「今日」算今天作答過幾個不同的題目：再練一次、換個方式再考不重複算，標記不算。
- 開始按鈕寫這一組的題數，下面一行寫今天還剩幾題；剩下不到 5 題或不到一組四分之一時，併進這一組。
- 只做模擬考或階段測驗的日子，連續天數照算，但不算題數。

## 3. 今天的清單

### 3.1 資料

`state.today` 多兩個欄位，其他欄位不變：

```
state.today = {
  date, newV, newG, newK, newL, newR, newC, newA,   // 原有
  plan: {                                          // 今天第一次需要時排好
    lists: { dueV: [key…], dueG, dueC, dueK, dueL, dueR, dueA, newV, newG, newC, newK, newL, newR, newA,
             kept: [key…] },                       // 重排時保留下來、已經作答的題目（§3.2）
    note, relearnN, n4Open,                          // 原本 dailyPlan() 回傳的其他欄位
    stage, start                                     // 排的當下的 state.stage 與 state.startChosen
  },
  ans: [key…]                                      // 今天作答過的題目，不重複
}
```

- 手動新增、沒有對到課程的錯題，作答時記成 `m:<錯題 id>`。
- `state.dailyLogs[日期].items`：當天 `ans` 的長度，每次加入時更新。學習紀錄用它顯示「N 題」。
- `state.dailyLogs[日期].ex`：當天作答的模擬考與階段測驗題數，只用來判斷那天有沒有學習（連續天數、學習紀錄）。

### 3.2 排清單

- 原本的 `dailyPlan()` 改名 `computeDailyPlan()`，計算方式這一版不變。
- 新的 `dailyPlan()`：`state.today.plan` 不存在、或排的當下的 `stage`、`start` 跟現在不同時，呼叫 `computeDailyPlan()`，把各清單的 key 存進 `state.today.plan`，然後 `saveState()`。之後每次呼叫都從存好的 key 還原成項目，濾掉 `ans` 裡已經作答的，再回傳跟原本一樣形狀的物件（`dueV`、`newV`…、`remaining`、`note`）。所以 `buildDailyQueue`、`extraQueue`、`renderToday`、離線語音的 `audioPrefetchItems` 都不用改呼叫方式。
- 找不到的 key（項目被隱藏或刪除）直接略過。
- `state.startChosen` 還是 `false` 時不存清單，每次即時算，避免新帳號在選起點前就排好一份空清單。
- 會讓清單重排的只有：起點剛選好（`start` 從 `false` 變 `true`）、學習階段改變（入門 ↔ 正課，例如入門四題選完、入門自動結束），以及整份 state 被換掉（匯入、還原、同步採用雲端版本；這時 `today` 會跟著換）。重排時，原清單裡已經作答的 key 保留在新清單裡，所以圓圈的「已做」不會倒退。
- 階段測驗後的批次標記、1.0.17 的入門自動標記、「前往下一單元」都**不**重排。因為清單早就排好了，標記不會讓圓圈跳，當天的聽力、閱讀也不會被吃掉。

### 3.3 記錄作答

`noteAnswered(key)`：key 不在 `state.today.ans` 時加入，並更新 `dailyLogs[今天].items`。呼叫的地方：
- `srsAnswer()`：所有會改排程的作答，包括每日練習、單元／單字／漢字練習、字卡、錯題循環和錯題練習。
- 錯題練習和錯題循環裡沒有對到課程的手動錯題：記成 `m:<id>`。

「手滑，不算」要能完整撤銷：撤銷資料多存一份 `ans` 和 `items`，撤銷時還原。

### 3.4 圓圈與數字

- `dayProgress()`：`total` = 清單裡的 key 數，`done` = 其中已在 `ans` 的數量。
- 圓圈：`ringHtml(done / total, '<b>57%</b>')`，中間只寫百分比，不寫題數。
- 今天做完時，標題寫「今天做了 N 題」，N = `ans.length`。
- 側欄「今日 N 題」：N = `ans.length`。
- 範圍分頁（隱藏的「範圍」tab）：照原樣列出剩下的待複習、新內容、另有幾題，數字改從今天的清單算。拿掉「這一組 N 題，做完還有 M 題」那一行，改到開始按鈕下面顯示。

### 3.5 開始按鈕與分組

- `buildDailyQueue` 取一組時：取完 `size` 題後，如果剩下的題數 ≤ 5，或少於 `size` 的四分之一，就全部併進這一組。
- 按鈕：「開始練習・這組 N 題」。今天剩下的比這組多時，下面加一行小字：「今天還有 M 題」（M = 清單裡還沒作答的題數）。
- 練習畫面的計數（`sessionCount`）不變：本組題數加上另外標示的「加考」。

## 4. 模擬考獨立

- `recordExamAnswer()`：只更新 `questionHistory` 和 `dailyLogs[今天].ex`，拿掉 `recordAction`、`recordAccuracy`、`srsAnswer`、`addMistake`。
- 結果頁拿掉「答錯的題目已加入錯題本。」。
- 階段測驗：`finishStageTest()` 原本呼叫一次 `recordAction('q', null, 'x')`，改成把這次作答的題數加進 `dailyLogs[今天].ex`。測驗本身仍然只記分數（1.0.17 的行為不變）。
- 模擬考題目選題用的 `questionHistory`（「先考沒考過的」「先考上次錯的」）不受影響。

## 5. 連續天數與學習紀錄

- `streakStats()`：某天有學習 = `dayTotal(e) > 0` 或 `e.items > 0` 或 `e.ex > 0`。
- 學習紀錄（最近幾天的列表）：
  - 有 `items` 的日子：chip 寫「N 題」，說明寫「N 題・作答 M 次（單字…）」。
  - 只有舊資料的日子：chip 和說明的第一段改成「作答 M 次」。
  - 有 `ex` 的日子，說明最後加「・模擬考與測驗 K 題」。
  - 列出的日子：任一數字大於 0 就列出。
- 行事曆的「有學習」也照同一個判斷。

## 6. 同步

- `sync-core.js` 的 `mergeToday()`：同一天時，`ans` 取兩邊的聯集（較新那份的順序在前），`plan` 照原本規則取較新那份。
- `dailyLogs` 的 `items`、`ex` 是數字，原本的「每個欄位取較大值」就適用。
- `tests/sync-core.test.js` 加一個測試：兩份同一天的 `today` 合併後，`ans` 是聯集。

## 7. 版本與文件

- `APP_VERSION` 與 `sw.js` 的 `CACHE` 改成 1.0.19；changelog 加一條。
- 今日頁「說明」分頁補一句：今天的題目一早排好，當天不會變；中途解鎖的新內容明天才排進來。

## 8. 測試

新增 `tests/e2e/test_today_list.py`（headless Chrome，跟其他 e2e 一樣自己起 http.server），先寫、先看它失敗，再改程式：

1. 練 12 題後「標記到這裡為止」（p1、熟悉）：圓圈百分比不變（清單的 done／total 不變），當天的聽力、閱讀還在清單裡。
2. 1.0.17 舊帳號的入門測驗自動標記：同上。
3. 一天四組、每三題錯一題：每一組做完後，清單總數都一樣。
4. 尾巴併組：清單剩 21 題、`sessionSize` 20 時，這一組是 21 題；剩 26 題時是 20 題，按鈕下方寫「今天還有 26 題」。
5. 模擬考答完 43 題（三分之一答錯）：`state.srs`、`state.mistakes`、`state.recent`、`dailyLogs[今天]` 的 `vocabCount`／`grammarCount`／`quizCount` 都沒變，`questionHistory` 有寫入，`ex` = 43。
6. 只考模擬考的日子：連續天數算這一天。
7. 「今天做了」與側欄：練一組有再練一次和換個方式再考時，數字等於不重複的題數；標記後不變。
8. 手滑撤銷：`ans`、`items` 一起還原。
9. 新帳號：選起點前不存清單；選「從零開始」後清單有入門內容。
10. 入門四題選完、正式進入正課：清單重排，已作答的仍算已做。
