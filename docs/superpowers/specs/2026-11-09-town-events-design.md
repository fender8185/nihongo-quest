# 小鎮事件 — 設計

日期：2026-11-09　狀態：使用者交給我照建議做（「一切都照你的建議來」）　基準：test = main 1.4.1（f12c032）
行號以 1.4.1 的 index.html 為準。只上測試站；上 main 由使用者決定。

## 1. 目標

在現有的地圖（院子、海邊、小鎮、大馬路公車站）加上更多 NPC 和地點，讓他們隨著課程進度一直有新的對話「事件」：

- 大約每兩三個學習日一個新事件，從入門（m0）一直到 N3 最後一個單元（m33），約 180 個。
- 每個事件用上那個單元的文法和學過的單字，對話中有 1–2 個「選回答」的地方，選對才往下。
- 不必涵蓋每一個文法點，但每個單元都要有，盡量多用。
- 角色有完整的個性、說話方式、作息和自己的故事線，讓人有代入感。

使用者的決定（2026-11-09）：
- 觸發：課程進度 + 學習天數（§4.1）。
- 形式：對話 + 選回答（§5）。
- 用字：大部分是學過的，少數沒學過的字加讀音和中文（§6）。
- 每一輪做完 commit 並推到測試站。
- 小鎮刪掉八百屋、本屋；新增可以走進去的「大眾食堂」和「居酒屋（晚上才開）」，用店裡不同身分的常客帶出不同領域的詞。
- 公車可以去的地方由我規劃（使用者提過祭典＋和服 NPC＋晚間限定、大眾澡堂、有名的地標）。
- NPC 會隨日夜在不同地點、店會打烊。
- 角色設定要細。

不變的事：學習排程、FSRS、題目、言靈的其他來源、已有的小春和ムギ的來訪與禮物。

## 4. 事件何時開

### 4.1 條件

每個事件屬於一個單元（`u`，m0–m33），同一單元內照順序。一個事件可以開，要同時符合：

1. **到了那個單元**：`u` 在目前單元（`state.currentUnit`；入門時是 m0）或之前。
2. **開始學那個單元**：那個單元至少有一個文法題（m0：入門的題目）有學習紀錄（`state.srs`）。
3. **隔了足夠的學習日**：上一個完成的事件之後，有練習的日子（`dailyLogs` 裡有作答的日子，不含完成當天）
   - 至少 2 天，若這個事件是目前單元的；
   - 至少 1 天，若是已經過了的單元（補進度：已經在 m5 的測試者，m0–m4 的事件一天一個補上來）。
   - 第一個事件不用等。
4. **前置事件做完**（`after`，可選）。
5. **主角找得到人**：事件的地點現在有營業，主角要找的人照作息現在在那裡。

一次最多只有一個事件在等（地圖上只會有一個「！」）。照順序挑第一個符合 1–4 的；如果它的人現在不在（第 5 條，例如居酒屋白天），就看同單元下一個符合的——晚上才能做的事件不會卡住白天玩的人，它會等到晚上再出現。

### 4.2 地圖上的提示

- 那個人頭上一個會上下浮動的「！」對話泡泡（在他所在的地點）。
- 院子往那個方向的指標、公車站（目的地在公車路線上時）也多一個小點，一路指過去。
- 進書房時一次的提示（toast）：「好像有人在小鎮上找你」（照地點換字）。
- 點那個人：主角走過去、轉向他、對話開始。

沒有事件時，點角色也會說話：從他「到目前單元為止」可說的閒聊句子裡隨機一句（閒聊也帶單元標籤，學到哪說到哪）。

## 5. 對話與回答

### 5.1 一行

沿用 `TALK` 的卡片（頭像、名字、身分、日文附讀音、🔊、中文），加上：
- **多個說話的人**：每一行標是誰說的（包括主角，主角的頭像用目前的穿搭）。
- **中文先收起來**：預設只看日文，點「中文」才展開（之後同一個事件記住你的選擇）。閒聊與舊的來訪照舊直接顯示中文。
- **生字小註**：沒學過的字用 `{漢字|讀音|中文}`，日文下方出現一行小註。

### 5.2 選回答

在要主角說話的地方，出現 2–3 個日文選項（主角的頭像）：
- 選對：選項變綠、主角說出那句、繼續。
- 選錯：選項搖一下變灰，出一行中文提示（為什麼不對，點出文法），可以再選。不扣分、不影響學習排程。
- 每個選項都可以按 🔊 聽。
- 選項標著它練的文法點（`pt`：文法題的 id 或單元），檢查腳本用它確認沒有用到還沒學的文法。

### 5.3 完成

- 最後一行之後：「事件完成」小卡＋ **+10 言靈**（記在 `koto.found['ev-<id>']`，所以會同步、不會重複給）。
- 少數事件給東西（例如健太給的麵包造型擺設、陽菜給的盆栽）：沿用 `gotItem` 特寫，東西用 `gift` 方式送（像小春的全身鏡）。
- 有些事件開通新地點（`opens`）或新角色的閒聊。

## 6. 日文的範圍

- 文法：只用到這個事件的單元為止學過的文法（`pt` 檢查）；句子盡量自然，必要的固定說法（いらっしゃいませ等）當成「一整句記」。
- 單字：以這個等級為止的單字為主（入門＋N5 到 m6，加 N4 到 m18，加 N3 到 m33）。比等級高的字一定要加中文小註。
- 所有漢字都加讀音（`{漢字|かな}`），跟現在的 TALK 一樣。
- 檢查腳本 `scripts/check-events.js`（`scripts/test.sh` 會跑）：
  - 讀音標記裡的字，在 VOCAB 找得到：等級不能高於事件的等級，除非有中文小註；找不到的字一定要有中文小註，或在「常用說法白名單」裡（人名、地名、店名、固定招呼）。
  - 標記外面不能有漢字（避免漏讀音）。
  - 選項的 `pt` 單元不能在事件單元之後；每個選回答至少一個對、一個錯。
  - 角色、地點、前置事件的 id 都存在；同一單元的事件數 4–7 個。
  - 每個 `u` 從 m0 到最後都有事件（做到哪個單元就檢查到哪個單元）。

## 7. 町の手帳

書桌上一本手帳（書房的東西，點了打開一個頁面，風格跟外婆的日記一樣）：
- 依人分頁：每個認識的人一頁（頭像、名字、身分、一段介紹——介紹會隨著事件多寫一句）。
- 每個人下面列已完成的事件標題；點了可以重看整段對話（選回答也可以再選，不給言靈）。
- 最後一頁：還沒去過的地方剪影（「？？？」）。

## 8. 資料格式

新檔案 `events.js`（跟 `data.js` 一樣版本號放在 index.html 的 `<script src>` 與 sw.js 的 PRECACHE，`EVENTS_VERSION`），一行一個事件方便 grep：

```js
const TOWN = {
  CAST: { kenta: { name: '森 健太', kana: 'もり けんた', role: 'パン屋', look: {...}, bio: ['…'], hours: [[5, 14, 'town', 'bakery'], [19, 22, 'izakaya', 'counter']] }, ... },
  CHAT: { kenta: [['m0', '{今日|きょう}も…', '中文'], ...], ... },
  EVENTS: [
    { id: 'm0-1', u: 'm0', who: 'miku', at: 'town', title: '「これ、なに？」', lines: [
        ['miku', 'これ、なに？', '這是什麼？'],
        { ask: '回答美玖：這是麵包。', opts: [['それはパンです。', 1], ['これはパンですか。', 0, '這是在問「這是麵包嗎？」'], ['あれはパンです。', 0, '麵包就在你手上，用「これ／それ」']], pt: 'm0' },
        ['kenta', '…', '…'] ], gift: null, opens: null, after: null }
  ]
};
```

- 一行 `[who, ja, zh]`；`who` 是 `hero` 或角色 id。
- 選回答 `{ ask, opts: [[ja, 對=1/錯=0, 錯的提示]], pt }`；選對之後主角說的就是那個選項。
- 狀態：`state.town = { done: { id: 日期 }, seen: { 角色: 1 }, stops: { station: 1 } }`。同步時 `done`、`seen`、`stops` 取聯集（sync-core 加一條）。
- 舊的 `NPCS`（小春、ムギ的來訪與禮物）保留不動；新角色的資料都在 `events.js`。
