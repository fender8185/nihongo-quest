# 出題規則減法 — 設計

日期：2026-10-30　狀態：使用者已確認（2026-10-30）；§8.3 在寫實作計畫時改成用答題前的紀錄判斷移出　版本：1.0.21（接在 1.0.20 之後）

取代 `2026-10-30-queue-scheduling-design.md` 的這幾處：§4 四顆答對升五顆、§5 錯題本 queue 與 50 題的算法、§8.1 聽力閱讀的標記與分散到期日、§8.2 入門四題。其餘照舊。

## 1. 問題

1.0.19–1.0.20 累積了 85 條裁決、41 個延後的小問題，規則多到講不完：

- 一題什麼時候再出現，有六種規則：
  - 三顆以下照到期日，每天最多 50 題
  - 四顆每天 5%
  - 五顆每天 3%
  - 錯題本每天 10%
  - 答錯的第 1、3、7 天
  - 入門題目五顆答對後移出

  錯題本的 10% 和 1/3/7 天管的是同一批題目，所以才要有「還沒到期先答對，算額外練習」這條。
- 兩個自動調整疊在一起：複習的目標記憶率看複習正確率在 87／90／93% 之間跳，新題數又看最近 100 題的正確率。
- 標記和入門有一串只為它們存在的例外：
  - 入門四題選三到五顆，還有預選
  - 聽力閱讀另外算 90–270 天
  - 四顆答對強制升五顆
  - 分散到期日（四顆、五顆根本不讀日期）
- 一次性的過渡規則還留著：1.0.17 舊帳號的入門測驗提示、`introPending`。

目標：規則少到能一口氣講完，以後加功能不必再一條條處理例外；考試日記得多少、每天題量不能變差。

## 2. 使用者的決定（2026-10-30）

- **保留分層。** 我先模擬過「全部回到一套間隔複習＋每天一個複習上限」（§11），記性差的人通過測驗、標記 2000 題後：
  - 上限 70：考試日只記得 78.6%，現在是 90.5%。
  - 不設上限：最多一天 215 題，現在是 142 題。

  分層就是為這個情況存在的，所以只砍它周圍的規則。
- **要做的：**
  - 記憶率固定 90%（§3）
  - 錯題本不再每天另外抽（§4）
  - 四顆答對不強制升五顆（§5）
  - 入門測驗跟其他階段一樣（§6）
  - 通過測驗不動聽力閱讀、標記不分散到期日（§7）
  - 拿掉過渡規則（§9）
- **不做「已熟練＝五顆」**（拿掉題型條件）。改成單字要五顆、而且假名拼字答對過（§8）。
- **不在範圍：**
  - 每天題量偏多（待決第 2 題）
  - 「見過一次答錯」
  - 新題數的規則
  - 聽力閱讀的間隔
  - 今天的清單一天排一次

## 3. 複習記憶率固定 90%

- `fsrsInterval(s)` 改用固定的目標記憶率：新常數 `RETENTION = 0.9`。
- 刪除：
  - `reviewAccuracy()`、`autoRetention()`
  - `srsAnswer` 寫 `state.reviewRecent` 的那一行
  - 「手滑，不算」撤銷 `reviewRecent` 的那一行
- `defaultState` 拿掉 `reviewRecent`，`normalizeState` 的陣列清單也拿掉它。舊資料裡的 `reviewRecent` 留著不管（跟 1.0.20 的負荷上限一樣）。
- `srsAnswer` 回傳的 `reviewed` 照留，錯題階梯和「錯題・額外練習」標籤要用。
- 學習者看不出差別：模擬差距 0.3% 以內。

## 4. 錯題本不再每天另外抽

### 4.1 規則

`computeDailyPlan` 的三顆以下到期複習分成兩部分：

| 部分 | 規則 |
|---|---|
| 錯題 | 在錯題階梯上（`onLadder`：答錯後第 1、3、7 天）、今天到期的，全部放進清單，不算在 50 題內。 |
| 其他三顆以下 | 照到期日排，最多 50 題（`SRS_DAILY_CAP`），其他明天。 |

錯題一定要放在 50 題外面：放在裡面的話，記性差的人大量標記後考試日只記得 81.2%。錯題一多，會把其他三顆以下的複習擠到隔天，越積越多。

### 4.2 拿掉的東西

- `QUEUE_RATE.mk`、`plan.mk`、`PLAN_LISTS` 裡的 `'mk'`。
- 今日頁「範圍」的「錯題本 N」。
- `buildDailyQueue` 裡的 `plan.mk`。
- 手動新增的錯題卡（`m:<id>`）不再進今天的清單，只在錯題本頁練（快速過一輪、用測驗練）。在那裡答過照舊算進「今天做了」（`noteAnswered('m:<id>')` 不動）。
- 只為清單裡的錯題卡寫的分支：
  - `planItem` 的 `m:`
  - `todayPlanKeys` 的 `m:` 過濾
  - `dailyQueue`、`startSession('daily')`、`buildDailyQueue` 裡的 `kind === 'm'`

  練習畫面、錯題本頁處理 `kind 'm'` 的地方不動。

### 4.3 不變的

- 錯題本頁、錯題本的進出規則（`addMistake`、`onCorrectForMistake`）照舊。
- 新題數照舊扣「錯題本每 10 條少 1 題」，算整本，含手動卡。
- 「還沒到期就先答對，算額外練習」照舊，因為字卡、單元練習、錯題本頁還是可能提早答到。只是每日清單不再出現提早的錯題。
- 今日頁「其中錯題 N」照舊。

### 4.4 升級當天

今天的清單如果已經排好，裡面錯題本 queue 的題目不再算在清單裡，圓圈的百分比可能變一次。隔天起照新規則排。

## 5. 四顆答對不再強制升五顆

- `srsAnswer` 刪掉「答之前是四顆、答對就至少五顆」那一行。四顆答對時照記憶強度算：
  - 在四顆的 queue 裡等了二十天左右才答對的，大多會算到五顆。
  - 記不太住的（難度高）留在四顆，照 5% 再排。
  - 當天剛標成四顆就答對的不會跳級。延後問題 M34 因此消失。
- 「五顆答對排回隊伍最後」照舊。入門題目的移出另見 §8.3。

## 6. 入門測驗跟其他階段測驗一樣

### 6.1 規則

- `finishStageTest`：不管哪個階段，通過就呼叫 `markPassedStage(stage, passSkipKeys(results))`，沒通過什麼都不改。
- 入門通過時，入門範圍（假名、入門單字、第 0 週句型）還不到四顆的設成四顆，其他跟 p1–p3 一樣：
  - 這次答錯的和錯題本裡的不設。
  - 答錯又沒學過的假名和第 0 週句型記成「見過一次答錯」，隔天起複習。
  - 答錯又沒學過的入門單字照舊留成新題。
  - 第 0 週算完成、講義算看過、`stage = 'main'`。
  - `currentUnit` 只往前不往回：入門的下一個是 m1。
- 已經在正課的帳號自己到課程頁考入門測驗：通過一樣設四顆，週次不變。

### 6.2 拿掉的東西

- 入門四題：
  - 常數與函式：`PRE_MARK_GROUPS`、`PRE_MARK_LEVELS`、`preMarkLevel`、`preMarkLevelName`、`preScores`、`preSuggest`、`preMarkOpen`、`preMarkScore`、`preMarkKey`、`preMarkStepHtml`、`preMarkApply`
  - 介面：`pre-mark-pick`、`handleKey` 裡四題那一段、結果頁的四題分支

  延後問題 M27、M28（四題的按鍵）因此消失。
- 標記只剩「四顆」一種等級：
  - `BULK_LEVELS`、`BULK_ORDER`、`bulkLevelOf` 簡化成「還不到四顆＝沒有紀錄或 b < 4」，四顆的穩定度用 `LEVEL_FROM_S[3]`（10 天）。
  - 課程頁的復原提示固定寫「四顆」。

### 6.3 文字

結果頁入門通過那句改成「通過了。已把入門還不到四顆的 N 題設成四顆。目前單元：第 1–2 週・…」，旁邊放「復原」。p1–p3 照舊寫「已把第 X 階段以前、還不到四顆的 N 題設成四顆」。

## 7. 通過階段測驗不動聽力、閱讀；標記不再分散到期日

### 7.1 聽力、閱讀

- `passMarkTargets` 只取聽力、閱讀以外、還不到四顆、不在略過清單的題目。
- 刪除 `spreadDueLR` 和等級裡的 `lr` 區間。延後問題 M24（沒人用的聽力日期設定）因此消失。
- 聽力、閱讀照自己的規則：每天 3 題、1 篇，答對 30／90／180 天後再出。已通過的階段裡還沒聽過、讀過的，之後照常當新題出。
- 階段測驗本身照舊會考聽力、閱讀（`stageItems` 不動）。

### 7.2 到期日

- `bulkApply` 寫的到期日改成照記憶強度算的日期：`addDays(t, fsrsDays(s, key))`，四顆大約 10 天後，跟「我會了」不帶參數時一樣。
- 這個日期在四顆、五顆的 queue 裡不會被讀到。代價只有一個：退回 1.0.20 以前的版本時，這些題目會擠在同幾天到期。
- 刪除 `spreadDue`、`bulkDailyBudget`、等級裡的 `due` 區間、`markKnown` 的 `dueDays` 參數。
- 單字頁「這 N 個字我都會了」不再分散：五顆在 queue 裡等，用不到日期。

## 8. 已熟練：五顆＋拼字答對過

### 8.1 標籤（`srsLevelLabel`）

- 新函式 `canSpell(v)` 判斷有沒有假名拼字題，`vocabFormats` 也改用它，兩邊同一個判斷：內建單字、讀音沒有漢字、2–8 個假名。
- 五顆（b ≥ 5）的單字：
  - `canSpell` 成立的，要拼字答對過（作答格式紀錄 `f['v-spell']` 有答對）才算已熟練，沒拼對過顯示「熟悉」。
  - 沒有拼字題的 24 個內建單字（17 個單一假名的字，像目、手、木，和 7 句長招呼語）和自訂字卡，五顆就算已熟練。
- 文法、假名、漢字、變化練習、聽力、閱讀：五顆就算已熟練。
- 按「我會了」、通過測驗設的、單字頁整批「我會了」，都一樣要拼字答對才算已熟練。
  - `known` 不再影響這個標籤，只留給兩個用途：單字頁的「取消熟練」按鈕，和錯題本的同步合併（`sync-core.js`）。
  - 練習回饋區的「這個字我已經會了」，在按過我會了（`known`）時不顯示。
- 刪除 `MASTER_FORMATS`、`formatsPassed`、`masterFormatsFor`。`recordFormat` 照留，換題型要用。
- 這條規則看的是題目種類，不看紀錄有沒有作答格式欄位：
  - 以前標記的文法、假名、漢字（帶空的 `f`）五顆就算已熟練。待決第 3 題和延後問題 M38、M39 不用另外清理。
  - 升級後，現在算已熟練、但沒拼對過的單字會顯示「熟悉」。開「熟練的字不標」時，它們會重新標出讀音，直到下一次拼對（§8.2）。

### 8.2 出題

- 四顆以上（b ≥ 4）、`canSpell`、還沒拼對過的單字，練習時一定出拼字，不管 `avoidFmt`。每日練習、加練、單元／單字練習都一樣。
- 不受影響：
  - 階段測驗只出選擇題（`choiceOnly`），照舊不出拼字。
  - 模擬考指定題型（`forceFmt`）。
  - 「換個方式再考」只給新字。
- 拼對之後照原本的權重輪替題型。
- 理由：五顆的字大約一個多月才輪到一次，拼字又只佔約四分之一的機會，不強制的話要好幾個月才碰得到拼字。

### 8.3 入門題目移出

- 移出（`out`）的條件從「五顆時答對」改成「已熟練時答對」，判斷用答題之前的紀錄：
  - 假名、第 0 週句型、沒有拼字題的入門單字：五顆就是已熟練，跟現在一樣。
  - 有拼字題的入門單字：要先拼對過、變成已熟練，再答對一次才不再出現。
- 例如：入門單字五顆、沒拼對過，用字卡答對，不會移出；下一次出拼字、拼對了，變成已熟練；之後再答對才移出。
- 用答題之前的紀錄，是因為題型在排程之後才記：拼對的那一題，排程算的時候還不知道它是拼字。
- 「取消熟練」（`unmarkKnown`）也清掉移出。延後問題 M10 順便修掉。

## 10. 文字

### 10.1 今日頁「說明」

> 今天的題目在第一次打開時排好，當天不會變；中途解鎖的新內容明天才排進來。三顆以下照記憶強度排複習，每天最多 50 題；答錯的題目幾題後再練一次，之後第 1、3、7 天各複習一次（不算在 50 題內），三次都對才離開錯題本。四顆每天出 5%、五顆每天出 3%（各最少 1 題、最多 30 題），等最久的先出。單字五顆、而且假名拼字答對過才算已熟練，四顆以上還沒拼對的，下次會出拼字。新題數看最近 100 題的正確率和錯題本，照還沒學的比例分給單字、文法、漢字。做完還想多學可以按加練，一輪只出新內容，題數等於今天的新題數，不出複習。

「換個方式再考」那一句照舊接在最後。

### 10.2 版本紀錄

**1.0.21 新增一條，三點：**

1. 錯題本不再每天另外抽 10%：答錯的題目照第 1、3、7 天回來，不算在三顆以下每天 50 題裡；手動新增的錯題卡在錯題本頁練。四顆答對不再直接升五顆，照記憶強度算（等了一陣子才答對的大多會升）。複習的目標記憶率固定 90%，不再看複習正確率調整。
2. 入門測驗通過跟其他階段測驗一樣：入門還不到四顆的題目設成四顆（這次答錯的和錯題本裡的不設），進入第 1 週，結果頁有「復原」，不再問四題。通過階段測驗不再改聽力、閱讀，它們照自己的節奏出。舊帳號的「先做一次入門測驗」提示拿掉了，要考可以到課程頁入門卡按「階段測驗」。
3. 單字要五顆、而且假名拼字答對過，才算「已熟練」（按「我會了」或測驗設的也一樣；沒有拼字題的字五顆就算）；四顆以上、還沒拼對過的字，練習時會出拼字。文法、假名、漢字五顆就算已熟練，以前批次標記過的也一樣。

**1.0.20 那一條：** 照程式裡的規則（推翻前一筆就改前一筆）：

- 刪掉入門四題那一點。
- 第二點拿掉「（入門四題選四顆也一樣）」。

**1.0.19 那一條：** 照 M41 的做法不動（更早的紀錄不改）。它還寫著「錯題本 10%」「四顆在哪裡答對都會升到五顆」，你要改也可以。

## 11. 模擬程式

### 11.1 改動

- `scripts/sim-schedule.js` 照 §3–§5 改：記憶率固定、沒有錯題本 queue、錯題不算在 50 題內、沒有強制升五顆。
- 從 `index.html` 抓的清單拿掉 `reviewAccuracy`、`autoRetention`，加上 `RETENTION`。
- 加一個選項 `--bulk N`：第 0 天先把 N 題設成四顆，像通過階段測驗。這次的比較就是用它跑的。以後調 50、5%、3% 這些數字時，兩種情況都要看。
- §8 只影響顯示和題型，不影響排程，模擬不管它。

  限制：拼字比選擇題難，四顆以上第一次拼字答錯的機會比較高，會多一些重練，模擬沒算進去。

### 11.2 預期的數字

1.0.21 的 `node scripts/sim-schedule.js`（不加和加 `--bulk 2000`）印出來的。標記的難度是 4，跟 app 新建的紀錄一樣。1.0.20 那一欄，是用同樣的設定跑 1.0.20 的規則：

| 情境 | 學習者 | 每天題量 | 最多一天 | 考試日記得 |
|---|---|---|---|---|
| 從零開始（第 101–200 天） | 強 | 105 → 105 | 116 → 115 | 97.0% → 97.3% |
| | 中 | 104 → 101 | 113 → 117 | 94.4% → 95.4% |
| | 弱 | 96 → 92 | 109 → 121 | 92.9% → 93.3% |
| 第 0 天標記 2000 題（第 31–100 天） | 強 | 122 → 118 | 131 → 130 | 98.0% → 98.3% |
