# 學習分析分級進度、課程進度推估與考試目標 — 設計

日期：2026-10-31　狀態：使用者已逐段確認（2026-10-31）　版本：1.0.26（接在 1.0.25 固定每組 20 題之後）

## 1. 需求

使用者（2026-10-31）要調整學習分析頁和設定：

1. 總進度加一個選單，分四種範圍：總進度（單字、文法、聽力＋閱讀、漢字，不含假名）、入門、N5、N4。
2. 「過去 7 天的練習量」換一種畫法。
3. 「最近 60 題正確率」改成 100 題。
4. 照過去的速度推估什麼時候到 N5、N4，依使用者要考的級別給建議；太慢時提醒可以用加練加速。
5. 「學完的預估」和「課程進度預估」合成一張卡。
6. 設定 → 學習 → 考試日期：除了日期，還要能選要考 N5 還是 N4。

## 2. 使用者的決定

- 「到某一級」的意思是：那一級的單字、文法、漢字都學過一次，也就是都有作答紀錄。期限沿用現在的算法：考試日期往前推三週，留三週做模擬考。
- 入門頁放假名、入門單字、入門文法（第 0 週）三個儀表。每個題目只屬於一個級別的頁面：入門的在入門頁，N5 的在 N5 頁，N4 的在 N4 頁。總進度頁算全部。
- 推估「到 N5」時，還沒學完的入門單字也算進去，因為要先學完入門才會到 N5。
- 過去 7 天用 C：上面三個摘要數字，中間一條趨勢線，下面一條各類占比。
- 推估用分題庫的算法（§5.2）。
- 聽力和閱讀不算進推估：它們每天固定出，題目從整個級別抽，不占每天的新題數。
- 模擬考頁的「考試倒數」也照目標級別推估，原本「剩下 N 個單元、每個單元幾天」那句拿掉。
- 目標級別預設是 N4，跟現在「全部學完」的推估一樣。
- 這次 `scripts/test.sh` 跑出 `ALL_OK` 後就直接推上去發布 1.0.26，不用再問（使用者 2026-10-31 授權）。

## 3. 總進度卡（`#progressCard`）

### 3.1 範圍選單

- 卡片說明的下面加一排 `.seg` 按鈕：總進度｜入門｜N5｜N4。每個按鈕是 `data-act="stats-scope"`，帶 `data-scope` 等於 `all`、`pre`、`n5` 或 `n4`，選中的那個 `aria-pressed="true"`。
- 選了哪個範圍記在模組變數 `let statsScope = 'all'`，不寫進 state，所以 app 開著的期間會一直記得，重新載入後回到「總進度」。這跟 `heroTab` 的做法一樣，只是離開頁面時不重設。
- 點按鈕會改 `statsScope`，然後重畫學習分析頁（`route()`）。

### 3.2 每個範圍的儀表

| 範圍 | 儀表（`data-kind`） | 標題 |
|---|---|---|
| `all` | `v`、`g`、`lr`、`k` | 單字、文法、聽力＋閱讀、漢字 |
| `pre` | `a`、`v`、`g` | 假名、入門單字、入門文法 |
| `n5`、`n4` | `v`、`g`、`lr`、`k` | 單字、文法、聽力＋閱讀、漢字 |

- 新函式 `itemLevel(it)` 回傳 `'PRE_N5'`、`'N5'` 或 `'N4'`：
  - 單字、漢字、聽力、閱讀：用 `it.lv`。漢字沒有 `lv` 時當作 N5。
  - 文法：第 0 週（`u === 'm0'`）是 `'PRE_N5'`，其他用所屬單元的 `lv`。
  - 假名：一律是 `'PRE_N5'`。
- `progressTotals(kind, scope = 'all')`：
  - 題庫：`v` 是內建單字，跟現在一樣不含自訂字卡；`g` 是 `REG.grammar`；`lr` 是 `REG.listen` 加上 `REG.read`；`k` 是 `REG.kanji`；`a` 是 `REG.kana`。
  - 範圍篩選：`all` 不篩，`pre`、`n5`、`n4` 只留 `itemLevel` 等於 `PRE_N5`、`N5`、`N4` 的題目。
  - 熟練度三階：
    - `v`、`k`、`a`：`srsLevelLabel` 是「已熟練」的算熟練；`b >= SRS_LEARNED` 算熟悉；其他算已學。跟現在單字、假名的算法一樣。
    - `g`：`ok >= 3` 算熟練，`ok >= 1` 算熟悉，其他算初識。跟現在一樣。
    - `lr`（新的）：`ok >= 2` 算熟練，`ok >= 1` 算熟悉，答過但還沒答對算初識。聽力、閱讀答對後要隔 30 天才會再出，所以第二次答對代表隔了一個月還懂。
  - 回傳的欄位跟現在一樣：`{ kind, total, seen, learned, mastered, n5, pct }`。`n5` 是 N5／N4 分界刻度的位置，只在 `scope === 'all'`、而且 kind 不是 `a` 時有值，等於 `itemLevel` 不是 `N4` 的題數，所以入門和 N5 都在刻度前面。其他情況是 0，不畫刻度。
- 儀表的標籤：`v`、`k`、`a` 用「已熟練、熟悉、已學」，`g`、`lr` 用「熟練、熟悉、初識」。
- 版面沿用 `.gauges`。手機上兩個一排，入門只有三個儀表，最後一個佔整排，現有的 CSS 已經會這樣排。

## 4. 過去 7 天的練習量與 100 題正確率

### 4.1 資料

新函式 `weekSummary()` 回傳：

- `days`：`weekPractice(7)`，最後一天是今天。
- `total`：這 7 天的題數合計。
- `avg`：`Math.round(total / 7)`。
- `change`：先算前 7 天（`weekPractice(14)` 的前 7 天）的合計 `prev`。`prev` 是 0 時 `change = null`，否則 `change = Math.round((total - prev) / prev * 100)`。
- `share`：`{ v, g, q }`，各是這 7 天單字（含漢字、假名）、文法、其他（聽力、閱讀、模擬考）的題數。

### 4.2 畫面

卡片標題還是「過去 7 天的練習量」，原本的直條圖整個換掉：

1. **三個摘要數字**：「7 天合計（題）」、「每天平均（題）」、「比前 7 天」。
   - `change > 0` 寫成「+N%」，用 ok 色。
   - `change <= 0` 寫成「−N%」或「0%」，用一般字色。
   - `change` 是 `null` 時寫「—」。
2. **趨勢線（SVG）**
   - 一條折線，底下塗一塊淡色面積，每天一個點，沒練習的那天點在最底下，今天的點用強調色。
   - 每個點有 `tabindex="0"`，`data-tip-title` 寫「10/29（四）：81 題」，沒練習寫「沒有練習」；`data-tip-body` 寫「單字 55・文法 22・其他 4」。提示沿用 `attachChartTips`。
   - 底下的軸寫星期幾，最後一格寫「今天」。
3. **占比條**：一條橫條，依 `share` 分成三段，下面寫「單字 N%・文法 N%・其他 N%」。這 7 天完全沒練習時不畫這條，改寫「這 7 天還沒有練習」。
4. **「明細」表格**：原本那張保留，收合起來。

不再用到的直條 CSS（`.cols`、`.col-axis`、`.collabel`、`.colbar`）一起拿掉。`.cseg`、`.seg-dot` 其他地方還在用，留著。

### 4.3 正確率卡

`recentAccuracy(60)` 改成 `recentAccuracy(RECENT_MAX)`，標籤改成「最近 ${RECENT_MAX} 題正確率」，也就是 100 題。`state.recent` 本來就保留 `RECENT_MAX` 題。答不到 12 題時跟現在一樣顯示「—」。旁邊另外三張數字卡不動。只有「還沒學的文法題」那張改成直接數 `REG.grammar` 裡沒有紀錄的題目，因為 `grammarPace()` 拿掉了（§5.5）。

## 5. 課程進度

### 5.1 速度

`perDay` 照現在 `paceAdvice()` 的算法：從最近 14 天裡第一個有 `dailyLogs.fresh` 的日子算起，求每天 `fresh` 的平均，那天之後沒有 `fresh` 的日子算 0。

兩種情況會改用今天排到的新題數 `dailyPlan().n || NEW_DEFAULT`，並設 `fallback = true`：

- 最近 14 天都沒有 `fresh`。
- 平均是 0。這種情況現在會顯示出「預計 null 學完」，這次一起修掉。

### 5.2 分題庫推估

每天的新題會照各題庫還沒學的量按比例分（`splitNew`），每個題庫裡又是先出 N5、再出 N4：單字要 N5 都學過一次才開 N4，漢字也一樣，文法照單元順序。所以每個題庫剩下的量會照同一個比例往下減，三個題庫會差不多同時學完；而每個題庫自己的 N5 部分，在它整體剩下的量減到只剩 N4 時就學完了。

正課的題庫只看還沒學的題目：

- `U.v`：內建單字，含入門單字。
- `U.g`：文法，不含第 0 週。
- `U.k`：漢字。
- `ΣU = U.v + U.g + U.k`。

到 N5 要學完的部分：

- `N.v`：入門單字和 N5 單字。
- `N.g`：N5 單元的文法。
- `N.k`：N5 漢字。

天數這樣算：

- `D_N4 = ΣU / perDay`
- `D_N5 = max(ΣU × N.i / U.i，i 是 U.i > 0 的題庫) / perDay`。N5 部分都學完了就是 0。
- 預計日期是 `今天 + ceil(D)`。

**入門階段**（`inPreStage()`）：

- 先算入門剩下的量：沒學過的假名、沒學過的入門單字、`introLeft()`，三個加起來是 `P`。入門要先學完，所以 `D_pre = P / perDay`。
- 學完入門之後，正課題庫裡的入門單字已經學過了，所以 `U.v`、`N.v` 都不含入門單字。
- `D_N5 = D_pre + max(ΣU × N.i / U.i) / perDay`，`D_N4 = D_pre + ΣU / perDay`。

**例子**：從零開始，每天 15 題新內容。

- `ΣU = 3261`，`U.v = 1661`、`N.v = 935`；`U.g = 1258`、`N.g = 415`；`U.k = 342`、`N.k = 104`。
- 各題庫的 N5 部分學完：
  - 單字：3261 × 935 / 1661 / 15 ≈ 122.4 天。
  - 文法：≈ 71.7 天。
  - 漢字：≈ 66.1 天。
- 所以到 N5 約 123 天，單字最慢；到 N4 約 218 天。直接相除會算成 97 天到 N5。

### 5.3 狀態與建議

新函式 `coursePace()` 回傳 `{ perDay, fallback, round, level, exam, deadline, left: { N5, N4 }, days: { N5, N4 }, finish: { N5, N4 }, state, late, need, gap, plan }`：

- `level` 是 `state.settings.examLevel`，`deadline` 是 `exam − 21 天`。
- `left`：各級還剩幾題。N5 是 `ΣN`，入門階段再加上 `P`；N4 是 `ΣU`，入門階段再加上 `P`。
- `round` 是一次加練的題數，等於 `dailyPlan().n || NEW_DEFAULT`。

`state` 依序判斷：

1. `'passed'`：考試日期已經過了（`examPace().daysLeft <= 0`）。
2. `'close'`：離期限不到一天，也就是離考試不到三週。
3. `'done'`：目標級別的部分都學過一次了。
4. `'ok'`：目標級別的預計日期不晚於期限。
5. `'late'`：比期限晚，`late` 是晚了幾天。

`'late'` 時要多算幾個欄位：

- `need = ceil(D_目標 × perDay / 離期限幾天)`：每天要學幾題才趕得上。
- `gap = need − perDay`：跟現在每天的差距。
- `plan`：換算成加練的頻率。
  - `gap <= round`：`{ every: max(1, floor(round / gap)) }`，代表每幾天做一次加練。用 floor 是為了保證趕得上。
  - `gap > round`：`{ times: ceil(gap / round) }`，代表每天要做幾次加練。`times >= 3` 時另外標 `heavy: true`。

### 5.4 文字 `courseText(p)`

學習分析卡和模擬考頁用同一段文字：

- `passed`：「考試日期已經過了。到設定裡改成下一次的日期，這裡會重新計算。」
- `close`：「距離考試只剩 N 天，不到三週：建議只做每天的練習與模擬考。」
- `done`，目標是 N4：「單字、文法、漢字都學過一次了：接下來照複習排程走，考前三週做模擬考。」
- `done`，目標是 N5：「N5 的單字、文法、漢字都學過一次了：接下來照複習排程走，考前三週做模擬考。」N4 還沒學完時，後面再加一句「照現在的速度，預計 X 學完 N4。」
- `ok`：「照最近每天約 P 題新內容的速度，預計 X 學完 {級別} 的單字、文法、漢字，比 D（考前三週）早 N 天。」
- `late`：前半跟 `ok` 一樣，只是寫「晚 N 天」，後面再接：「要趕上，每天約需 NEED 題新內容（現在約 P 題）：」，然後依 `plan`：
  - `every == 1`：「每天做完當天的練習後按 1 次加練就趕得上。」
  - `every > 1`：「大約每 N 天，做完當天的練習後按 1 次加練就趕得上。」
  - `times` 是 2：「每天做完當天的練習後按 2 次加練就趕得上。」
  - `heavy`：不接上面那個冒號，整段改成「要趕上，每天約需 NEED 題新內容（現在約 P 題），等於每天加練 K 次，太吃力了：可以考慮先考 N5，或把考試日期往後延（JLPT 每年 7 月、12 月各一次）。」目標是 N5 時拿掉「先考 N5，或」。
- `fallback` 時，速度那一句改成「最近 14 天沒有學新內容，照每天排到的 P 題新內容推算」。

上面的 P 都是 `Math.round(perDay)`。

### 5.5 課程進度卡（`#courseCard`）

這張卡取代「課程進度預估」和「學完的預估」（`#planAdvice`），放在學習紀錄卡後面，也就是原本「課程進度預估」的位置。

- **標題列**：標題「課程進度」，右邊放一個狀態標籤：`ok` 是「趕得上」（ok 色），`late` 是「稍慢」（warn 色），`done` 是「學完了」（ok 色）；`passed` 和 `close` 不放。
- **說明列**：「目標 N4・考試 2027/07/04（06/13 前學完，留三週做模擬考）・照最近 14 天每天約 P 題新內容推算」，`fallback` 時改成 §5.4 的說法。旁邊放「更改目標」按鈕，`data-act="settings-learn"`，會打開設定的學習頁。
- **時間軸 SVG**：只在 `ok`、`late`、`done` 時畫。
  - 起點是今天，標上 N5 和 N4 的預計日（已經學完的那一級不畫點）、期限（虛線）和考試日（實線）。
  - 軸的長度取考試日和各預計日裡最晚的一個。
  - 目標那一級的點，`ok` 時用強調色，`late` 時用 warn 色；另一級用 ok 色。
  - 靠近右邊的標籤改成靠右對齊，免得被切掉。
  - 軸最長到考試日的兩倍。超過的點都放在最右邊，共用一個標籤，例如「N5、N4 →」，日期寫在下面的兩行文字裡。
- **`passed`、`close`、`done` 時**：多一段文字，寫 `courseText(p)`。`passed`、`close` 時不畫時間軸，也不列兩行文字。
- **兩行文字**：N5、N4 各一行，寫「預計 YYYY/MM/DD 學過一次」，下面一行小字寫「還有 N 題」。目標那一行再加「目標，比期限早／晚 N 天」。已經學完的那一級寫「都學過一次了」。
- **建議框**：只在 `late` 時出現，寫 §5.4 的加練建議。
- **「各題庫明細」**：收合起來，內容是原本 `#planAdvice` 那張表，列假名、單字、文法、漢字、聽力、閱讀各「已學 / 總數」和「還沒學」。

拿掉 `paceAdvice()`、`finishText()`、`grammarPace()` 和 `planAdviceHtml()`，改用 `coursePace()`、`courseText()` 和 `courseCardHtml()`。`examPace()` 留著，因為 AI 學習建議還會用到它的單元欄位。

### 5.6 模擬考頁「考試倒數」

- 天數下面那行改成「距離 2027/07/04 JLPT N4」，後面加上目標級別。
- 狀態標籤改用 `coursePace().state`，對應跟 §5.5 一樣。原本照「每個單元幾天」判斷的「稍微落後／進度充裕／進度正常」拿掉。
- 原本「剩下 N 個單元，每個單元……」那段拿掉，只留 `.hero-advice` 裡的 `courseText()`。

### 5.7 AI 學習建議

提示裡「距離 JLPT（日期）」改成「距離 JLPT {級別}（日期）」，讓 AI 知道目標級別。其他內容不動。

## 6. 設定

- `defaultSettings()` 加上 `examLevel: 'N4'`。
- `normalizeState()`：`examLevel` 不是 `'N5'` 也不是 `'N4'` 時，改回 `'N4'`。
- 設定 → 學習：原本「考試日期」那一列改名叫「考試」，同一列放級別下拉選單（N5、N4，`data-change="setting" data-key="examLevel"`）和原本的日期欄位。說明改成「學習分析和模擬考頁會照這個級別和日期推估進度。」

## 7. 測試

照 TDD：先寫會失敗的測試，看它失敗，再實作。

### 7.1 新測試

**總進度卡**

- 四種範圍各自的儀表種類和題數。預期的題數用測試自己的篩選數出來，不呼叫 `progressTotals` 或 `itemLevel`。
- 總進度頁沒有假名，刻度只在總進度頁。
- 切到 N5、換到別頁再回來，還是 N5。
- 聽力＋閱讀的三階：準備答過沒答對、`ok = 1`、`ok = 2` 的紀錄，看儀表上是不是分別算初識、熟悉、熟練。

**過去 7 天**

- 用 14 天的紀錄檢查合計、平均和比前 7 天的百分比，預期值先手算好。
- 前 7 天沒練習時顯示「—」。
- 檢查占比、點的提示內容和明細表格。
- 7 天都沒練習時，顯示「這 7 天還沒有練習」。

**正確率**：放 100 題紀錄，前 40 題錯、後 60 題對，要顯示 60%。照 60 題算會是 100%。

**推估**（`coursePace()`，每天 10 題）

- 只剩 30 個 N5 單字沒學：N5 和 N4 都是 3 天後。
