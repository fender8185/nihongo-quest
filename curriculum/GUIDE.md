# 課程大綱整理指南（給內容小隊）

你要把候選清單整理成 Nihongo Quest（給台灣學習者的 JLPT app）的課程大綱：分主題、寫中文意思、篩掉不該教的字、把文法點分成單元。這份是規則；設計在 `docs/superpowers/specs/2026-10-31-curriculum-n3-n1-design.md`，格式在 `docs/superpowers/plans/2026-10-31-curriculum-outline.md` 的 Global Constraints。

## 要讀的檔

- 候選清單：`curriculum/candidates/n5.json` … `n1.json`。每一列是一個字（`w` 寫法、`r` 讀音、`status`）、一個漢字或一個文法點（`p` 句型、`key`、`src` 來源）。
  - 只處理 `status` 是 `new` 和 `variant` 的字，以及 `new` 的文法點。
  - `in-app` 是 app 已經有的，`dup` 是更低一級（或同一級前面）已經列過的，都不用管。
- `curriculum/candidates/REPORT.md`：數字和每個 `variant` 對到的 app 字。
- `curriculum/candidates/app-grammar.md`：app 現有 18 個單元教過的文法。
- 寫好就跑 `node scripts/curriculum/check-outline.js`，跑到你那一級沒有 `PROBLEM` 為止。

## 背景：清單是舊制 JLPT 來的

2010 年改制以後，官方不再公布單字和文法清單。這份清單（Jonathan Waller 整理）是從舊制的官方清單對應過來的：N1、N2、N4、N5 大約等於舊 1、2、3、4 級，N3 是新設的。所以：
- 有些字已經過時或很少用，要挑出來（見下面「篩掉」）。
- N3 和 N2 的分界本來就是估的。覺得某個字明顯放錯級，不要搬，在 `dropped` 寫「應該在 N2」之類的原因，讓使用者決定。

## 單字

**主題**
- 每一級 15–20 個主題，每個主題至少 20 個字。
- 名稱和說明的寫法跟 app 現有的一樣：
  - N4 的例子：「居家生活｜家事、物品、日常」「思考與抽象｜想法、意見、抽象名詞」「自他動詞｜成對的自動詞與他動詞」
  - N5 的主題：問候與溝通、疑問與指示、時間、數量、人物與家庭、身體與健康、飲食、衣物與購物、居家生活、學校與工作、交通與移動、地點與位置、自然與天氣、興趣與休閒、動作、形容與狀態、副詞與接續
  - 高級可以有比較抽象的主題，例如「經濟與社會」「書面語與副詞」「擬聲擬態語」。
- 一個字只放一個主題，照最常用的意思放。

**中文意思 `m`**
- 繁體中文、台灣用語，12 個字以內，跟 app 現有的寫法一樣。例：「趕快、急忙」「養育；培育」「豐盛的菜餚；請客」「音信；消息」。
- 不同意思用「；」隔開，近義用「、」。

**先查 app 有沒有**
- 比對程式只認得寫法、送り仮名和する的差別，抓不到其他形式。N5／N4 那次就漏了一緒／一緒に、大きな／大きい、すぐに／すぐ、皆／みんな、舟／船、込む／混む、下りる／降りる。
- 留下一個字之前，先用讀音或寫法查 app：
  `node -e 'const D=new Function(require("fs").readFileSync("data.js","utf8")+";return DATA;")();const q=process.argv[1];D.VOCAB.filter(v=>v.r.includes(q)||v.w.includes(q)).forEach(v=>console.log(v.id,v.w,v.r,v.m,v.lv))' <讀音或寫法>`

**篩掉（`dropped`，每個都要寫 `why`）**
- `variant` 是同一個字、只是寫法不同 → 篩掉，`why` 寫「app 已有：<id>（<app 的寫法>）」。是不同的字 → 照新字分主題。
- app 已經有、只是形式不同（上面那幾種）→ 篩掉，`why` 一樣寫「app 已有：<id>（<app 的寫法>）」。
- 兩個候選其實是同一個字（コンピュータ／コンピューター）→ 留一個，另一個篩掉，`why` 寫「跟<留下的字>是同一個字，只收一個」。
- 清單把字拼錯（楽む 應該是 楽しむ）→ 篩掉，`why` 寫「清單拼錯，應為<正確的字>」；正確的字放進 `added`。
- 過時或現在很少用的字（テープレコーダー、字引、看護婦）→ 篩掉，`why` 寫「過時」或「少用」。有現代說法的，放進 `added`（例：看護師），也要分進主題。
- 清單解析壞掉的列（字被切斷，例如「すみませ」）→ 篩掉，`why` 寫「清單資料不完整」；完整的字如果 app 沒有，放進 `added`。
- 純人名不收；國名、地名照收。
- 疑似放錯級 → 見上面「背景」。

**讀音**
- 留下的字，讀音欄解析壞掉的（例如「十」寫成「じゅうとお」、「キログラム」寫成「キロ」）→ 改成正確的讀音。
- 篩掉的字照候選原樣。

**補字（`added`）**
- 只有三種情況：取代過時的字、修補清單壞掉的列、更正清單拼錯的字。
- 每個都要寫 `why`，也要放進某個主題。不能是 app 已經有的字。

## 漢字

- `kanji` 填這一級 `new` 的候選漢字，順序用 `scripts/curriculum/check-outline.js` 的 `kanjiOrder(大綱所有字, 候選漢字)` 算，不要自己排。

## 文法點與單元

- 每個單元 6–10 個點，同一種功能的放一起：推測、時間、原因、逆接、條件、對象與立場、程度、強調與限定、判斷與義務……
- 單元編號：N3 從 m19 開始；N2、N1 接著上一級的最後一號。
- `short` 是 8 字以內的單元名（例：「授受」「假定條件」）；`title` 是「名稱：句型・句型・句型」（例：「授受：あげる・くれる・もらう」）。
- 每個點：
  - `p`：句型，用「〜」開頭，例如「〜うちに」。
  - `m`：中文意思，20 字以內。
  - `keys`：它涵蓋的候選 key。
  - `src`：來源，照候選的 `src`。
- 同一個句型的變體合成一個點（「〜うちに／〜ないうちに」），`keys` 都列。兩個來源寫法不同但其實是同一個點（Waller「〜わけです」、OpenJLPT「〜わけだ」），也合成一個。
- app 已經教過的點 → 放 `covered`，`by` 寫 app-grammar.md 裡教它的單元（m1–m18），`why` 寫理由（例：「m12 已教らしい」）。
- 兩個來源等級不同時照候選清單的歸屬；真的要換級，放 `moved`，`to` 寫哪一級、`why` 寫原因，並在那一級的單元裡放這個點。
- 階段：每級 2 個（N1 可以 3 個），照順序分完所有單元。標題例：「第四階段：N3 文法」「第五階段：N3 進階與總複習」；N2 是第六、第七；N1 從第八開始。

## N5／N4 缺口（`curriculum/gaps-n5n4.json`）

- 一樣處理 N5、N4 `new` 和 `variant` 的字，但不分新主題。
- 每個字的 `c` 從 app 同一級現有的主題挑（`DATA.THEMES.N5`、`N4`；N4 的列表見上面「主題」）。
- 格式：`{ "N5": { "words": [{ "w", "r", "m", "c" }], "dropped": [{ "w", "r", "why" }], "added": [{ "w", "r", "m", "c", "why" }] }, "N4": { … } }`。`added` 可以省略。

## 使用者的決定（2026-10-31，審查後）

這幾條蓋過上面的規則。

1. **全部用現代寫法，跟 app 一致**（出かける、見つける、乗り換え）。
   - 送り仮名照現代標準：浮ぶ→浮かぶ、戸締り→戸締まり、見積り→見積もり、申出→申し出。
   - 複合詞裡一般寫假名的部分改假名：話し掛ける→話しかける、見掛ける→見かける、手掛かり→手がかり、引っ掛ける→引っかける。
   - 常用漢字表以外、一般寫假名的字改假名：纏める→まとめる、繋がる→つながる、溜まる→たまる、揃う→そろう、寧ろ→むしろ、尤も→もっとも、蝋燭→ろうそく、狡い→ずるい。
   - 不確定時照 NHK 和報紙的寫法。
   - 做法：舊寫法放 `dropped`，why 寫「舊寫法，改收<新寫法>」；新寫法放 `added`，也要分進主題。新寫法如果 app 或別級已經有，就只篩掉，why 寫「舊寫法；app 已有：<id>」或「舊寫法；N? 已收：<新寫法>」。
2. **同訓異字：意思明顯不同才分開收**（遭う／会う、診る／見る、治す／直す 分開收）。意思一樣的只收一個。
3. **動詞的名詞形**：app、同級或低級已經有那個動詞時，名詞形意思跟動詞一樣就不收（助け、頼み、慣れ、諦め），why 寫「動詞已收：<動詞>」。名詞形有自己的意思才收（届け、作り）。
4. **字首、字尾、量詞都收**。
   - 之前因為「app 沒有這種卡片」或「是文法點」篩掉的，要收回來：不、無、全、大、小、旧、昨、来、正、〜的、〜だらけ、〜向け、毎、〜難い……。
   - N1 放進「語言與造詞」；N3、N2 放進最接近的語言類主題。
   - 意思寫成「（接頭）不～」「（接尾）～的」這種格式。
   - app 已經有的量詞照舊篩掉（app 已有）。
5. **放錯級的字要搬**，照 `curriculum/work/moves.json`。
   - 每一列：`from` 那一級的 `dropped` 裡，why 改成「搬到 <to>」（例：「搬到 N1」「搬到 N4 缺口」）。
   - `to` 那一級的 `added` 加上 `as` 的寫法和讀音，why「從 <from> 搬來」，也要分進主題。N5、N4 放進缺口檔的 `added`，`c` 用 app 該級的主題。
   - 兩列搬成同一個字時只加一次。
6. **同形異讀都收**。`node scripts/curriculum/check-outline.js` 印出的 `homograph missing: 字（讀音）`，是同一個寫法的另一個讀音，當成另一個字分進主題。
   - 讀音照清單，不要改，檢查程式靠讀音認它。
   - 清單壞掉的讀音（キロ 讀成 キログラム、誰 讀成 だれか、十 讀成 じゅうとお）放 `dropped`，why「清單資料錯誤」，r 照清單原樣。
   - 這個讀音的字如果別級或 app 已經有 → `dropped`，why「N? 已收：…」或「app 已有：…」。
